# 이미지 방향(EXIF) — 설계 정본 (2026-08)

> **위상: 구현 완료.** 사용자 판정으로 **C안(둘 다)**을 채택했다(2026.08.22).
> 코드의 단일 소스는 `util/ExifOrientation.kt`(규칙)와 `util/ImageOrientationIo.kt`(손)이다.

## 1. 무엇이 문제였나

안드로이드 `BitmapFactory`는 **EXIF 방향을 무시하고** 센서가 기록한 픽셀을 그대로 준다.
폰 카메라는 대개 픽셀을 세우지 않고 방향만 EXIF에 적으므로, 그 값을 적용하지 않으면
세로로 찍은 사진이 전부 눕는다.

**이 저장소는 그 적용을 한 곳도 하지 않고 있었다** — `ExifInterface` 참조 0건이고,
디코드하는 자리 넷이 전부 생 `BitmapFactory`였다(썸네일 · 전체 화면 뷰어 · AI 전송 · 편입).

| | 앱 안에서 보이던 모습 | 폴더로 내보낸 사본 |
|---|---|---|
| **압축 꺼짐**(기본값) | 원본 바이트 저장 → **누워 보임** | 원본 그대로 → 외부 뷰어에선 **정상** |
| **압축 켜짐** | 픽셀을 세우지 않고 재인코딩 + EXIF 소멸 → **누워 보임** | **누운 채로 영구 확정** |

압축 갈래가 특히 나빴다 — EXIF가 사라져 **원래 방향을 알 방법이 영영 없어진다.**

## 2. 채택한 것 — 두 갈래를 갈라 쓴다

**한쪽만으로는 빈 곳이 남는다.** 표시만 고치면 압축 갈래가 계속 방향을 잃고,
편입만 고치면 무손실로 저장된 원본이 계속 눕는다. 그래서 둘 다 한다.

| 갈래 | 처방 | 왜 |
|---|---|---|
| **편입·재압축**(압축 켜짐) | **픽셀을 세워서 저장**하고 EXIF는 남기지 않는다 | 어차피 재인코딩이라 추가 손실이 0이고, 저장된 픽셀이 곧 보이는 것이 되어 외부 뷰어·내보낸 사본까지 한 번에 맞는다 |
| **무손실 경로**(압축 꺼짐) | 원본 바이트를 **그대로 둔다** | 설정이 약속한 것이 그것이다. 방향은 EXIF에 살아 있으므로 **그리는 자리**가 세운다 |
| **그리는 자리 셋**(썸네일·뷰어·AI 전송) | `ImageOrientationIo.applyFileOrientation` | 하나라도 빠지면 화면마다 방향이 갈리고, 그때 사용자는 어느 쪽이 진짜인지 알 수 없다 |

**무손실 약속은 깨지 않는다** — 세우는 것은 이미 재인코딩하는 갈래뿐이다.

## 3. 이미 누운 채 저장된 것 — 인앱 회전 (사용자 판정)

압축을 켠 채 들여온 사진은 EXIF가 없어 **자동으로 되살릴 수 없다**(무엇이 원래 방향인지
알 방법이 없다). 그런데 앱에는 회전 수단이 하나도 없었다. 그래서 전체 화면 뷰어에 회전
버튼을 세웠다 — `util/ImageRotation.kt`.

- **무손실을 먼저 시도한다:** JPEG면 **EXIF 태그만** 고쳐 픽셀을 다시 쓰지 않는다.
  네 번 돌려 제자리로 와도 원본 그대로다.
- **폴백은 픽셀 회전:** 태그를 못 쓰는 포맷(투명도가 있어 PNG로 인코딩된 파일)일 때만.
  판정은 **확장자가 아니라 1번의 결과**로 한다 — 이 저장소는 파일명을 언제나 `.jpg`로
  짓지만 실제 포맷은 내용이 정한다.
- **줄이지 않는다.** 메모리가 모자라면 회전을 **하지 않고 실패로 알린다** — 방향만
  고치려다 조용히 화질을 잃는 것이 더 나쁘다.
- **확인창을 두지 않는다.** 되돌리기가 회전 버튼 자신이다(세 번 더 누르면 제자리).
  R-4가 요구하는 것은 *되돌릴 수 없는* 처분의 사전 고지다.

**경로는 바뀌지 않는다** — 같은 파일에 그대로 쓰므로 정리 폴더 왕복의 토큰이 그대로 살고
(파일명 불변) 캐릭터·작품·세계관의 경로 참조도 손댈 필요가 없다. 개명이 아니므로
`FolderRoundtripPrefs`의 별칭도 남기지 않는다.

## 4. 반려한 것

- **무손실 경로도 편입 때 세우기** — 설정이 명시적으로 약속한 무손실이 깨진다.
  표시 쪽에서 세우면 같은 결과를 얻으면서 약속이 산다.
- **기존 라이브러리 일괄 소급 회전** — 무엇이 누웠는지 앱이 알 수 없다(EXIF가 없다).
  기계가 판정할 수 없는 것을 일괄로 바꾸면 멀쩡한 것을 눕힌다. 사람이 보고 정하는
  회전 버튼이 그 자리를 맡는다.

## 5. 어디까지 자동으로 확인되나

방향은 **화면에서만 보인다** — 순수 시험이 볼 수 있는 것은 여덟 값의 표(`ExifOrientationTest`,
회전 누적·반전 보존·미지값 처분 포함)뿐이고, 읽는 손·그리는 손은 Android라 하네스가 못 돈다.
그래서 **틀리기 쉬운 것을 표로 몰아넣고** 손은 판단을 한 줄도 갖지 않게 했다.
실기기 몫은 `docs/device_walkthrough.md` **S13**(여섯) · **S2**(둘) — 절 번호 `3-151`.
