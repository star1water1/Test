# 인앱 텍스트 스타일 가이드 + 개혁 계획 (2026-07)

> **위상: P3(인앱 도움말 체계, U-7+U-8)와 한 몸이다.** 화면 문구가 길고 어려웠던 근본 원인 중
> 하나가 "도움말이 없어서 모든 예외를 그 자리에서 설명해야 했던 것"이므로, 텍스트 개혁과
> 도움말 체계는 같은 분업 설계(화면 = 무엇 / 도움말 = 왜·예외·비용) 위에서만 함께 성립한다.
> 파일럿(9장)이 P3의 첫 적용(U-8)을 겸한다.

## 0. 왜 하는가 — 진단 요약

사용자 지적: 번역체 말투와 개발자 언어가 섞여 있고, 특히 필드 편집 **고급탭**처럼 세분화된
기능이 몰린 곳에서 "뭐가 뭐지?"가 심하다. 간결함은 유지하되 그 선 안에서 쉬운 말로.

전수 조사(strings.xml 2,061건 + 코드 하드코딩 문구) 결과, 문제는 넷으로 갈린다:

| # | 문제 | 예 | 처방 |
|---|---|---|---|
| ① | **용어** — 우리말 대체가 있는 개발·문서 어휘 | 매핑, 그룹핑, 산출물, 카탈로그, 정규화 | 용어 사전(5장)으로 교체 |
| ② | **목적문 부재** — 설정이 라벨 하나로만 등장 | `랜덤 생성`, `상위 % 표시`, `구조화 입력` | 목적문 규칙(4-1) + R-25 |
| ③ | **결과 연결 부재** — 설정의 효과가 어디에 나타나는지 안 알려줌 | 랜덤 생성 ↔ 폼의 🎲 버튼 | 목적문에 "어디에" 포함 |
| ④ | **말투** — 해요체 혼입·붙여쓰기·번역체 | "찾을 수 없어요", "확인해주세요", "존재합니다" | 톤 규정(3장) + 도구 |

핵심 발견: **고급탭이 심한 것은 우연이 아니다.** `목록 카드 표시`(B-5)와 AI 섹션(P-A)처럼
최근에 만든 설정에는 설명 한 줄이 붙어 있지만, 그보다 오래된 섹션은 전부 라벨 하나뿐이다.
"설정 아래 한 줄" 관행이 늦게 생겨서 옛 섹션이 이전 관행인 채 남은 것 — 그래서 이 문서는
문구 교정 목록이 아니라 **관행을 규칙과 도구로 굳혀 재발을 막는 것**을 본체로 삼는다(7장).

기계 검출 실측(2026.07.28, `tools/check_text_style.sh` 기준선): **59건** —
붙여쓰기 25 · 금지 용어 18 · 해요체 16. 기계가 못 잡는 유형(②③, 번역체 문형)은 파일럿과
전개(9·10장)에서 화면 단위로 잡는다.

## 1. 적용 범위

**대상 = 사용자 눈에 닿는 모든 한국어.**

- `strings.xml` 전체
- 코드 하드코딩 사용자 노출 문구 — 순수 계층이라 리소스로 못 옮기는 곳
  (AI 결과 문구, 엑셀 가져오기 행 오류·경고, 엑셀 '사용 안내' 시트, 휴지통 요약 등.
  파일 목록은 `tools/check_text_style.sh`의 `KT_USER_FACING`이 단일 소스다)
- 엑셀 내보내기 파일 속 안내 문구(사용 안내 시트·열 이름)

**제외:** 로그(`AppLogger`)·코드 주석·`docs/` — 개발자 문서는 지금 문체(개조식·한자어 허용)가
맞다. 이 가이드는 문서 문체를 화면에 새지 않게 하는 담이지, 문서 문체를 바꾸는 것이 아니다.

**독자 기준:** 엑셀은 다뤄 봤지만 개발 용어는 모르는 창작자. "처음 연 사람이 라벨만 읽고
무엇이 달라지는지 알 수 있는가"를 기준 질문으로 삼는다.

## 2. 대원칙

1. **간결의 선 안에서 쉬운 말.** 쉬운 말 = 길게 풀어쓰기가 아니다. 문장을 늘리지 말고
   어휘를 바꾸고, 넘치는 설명은 도움말로 옮긴다.
2. **정확성을 팔아 쉬움을 사지 않는다.** 오류문이 원인+교정 경로를 갖추는 기존 문화(변수
   제어)는 자산이다 — 문구를 다듬되 정보를 깎지 않는다.
3. **화면/도움말 분업.** 화면에는 "무엇이 어떻게 되는지"까지. "왜 이렇게 설계됐는지,
   예외는 뭔지, 비용은 얼마인지"는 `?` 도움말로.

## 3. 톤 규정

| 자리 | 톤 | 예 |
|---|---|---|
| 안내·설명·오류 (기본) | **합니다체** | "값이 저장되지 않았습니다" |
| 지시(버튼·입력 유도) | **~하세요** | "이름을 입력하세요" |
| 확인 질문 (다이얼로그) | **~하시겠습니까?** | "정말 삭제하시겠습니까?" |
| 빈 화면 유도문 (유일한 예외) | **~해 보세요** | "캐릭터를 추가해 보세요" |
| 오류 **목록의 행 단위 항목** (엑셀 결과 등) | 개조식 허용 | "행 12: 세계관 '북부'를 찾을 수 없음" |

- **해요체 금지** ("~어요/에요/네요/~ㄹ게요"). **전개 5단계로 잔여 0건**(2026.07.30) —
  기준선 파일(`tools/text_style_baseline.txt`)이 **0바이트**이고, 그 크기가 곧 증명이다.
  건수를 여기 적지 않는 이유는 이제 셀 것이 없기 때문이며, 다시 생기면 검사기가 실패로 알린다.
- **확인 질문 "~할까요?" 금지** (사용자 판정 2026.07.28) — "~하시겠습니까?"로 통일.
  판정과 동시에 기존 24건을 일괄 교체했고 `check_text_style.sh` R1이 재유입을 막는다.
- 개조식 허용은 **스캔되는 목록**에 한한다. 다이얼로그 본문·토스트에는 쓰지 않는다.
- 이모지·기호는 이미 자리 잡은 것만 유지(🎲 ✨ ⓘ 🔒) — 새 문구에서 장식용으로 늘리지 않는다.

## 4. 문장 규칙

### 4-1. 목적문 — 모든 설정 스위치·섹션의 의무 (R-25)

**패턴: "켜면/쓰면 [무엇]이 [어디]에서 [어떻게] 됩니다."** — 문제 ②(목적 부재)와
③(결과 연결 부재)을 한 문장이 같이 해결하도록 "어디"를 반드시 포함한다.

```
나쁨: 랜덤 생성                          (라벨만 — 켜면 뭐가 어디에 생기는지 모름)
좋음: 랜덤 생성
      켜면 입력 폼에 🎲 버튼이 생겨, 아래 범위 안에서 값을 무작위로 만들어 줍니다.
```

이미 이 형태인 곳(`목록 카드 표시`, AI 섹션, 창작도 카드)은 손대지 않는다 — 그 관행을
옛 섹션으로 소급하는 것이 목적이다.

### 4-2. 오류문 — 2부 형식 (기존 자산의 명문화)

**[무엇이 안 됐는지] + [다음에 뭘 하면 되는지].** 원인 불명이면 불명이라고 말한다.
"다시 시도하세요"는 재시도가 실제로 결과를 바꿀 때만 쓴다(결정적 실패에 붙이지 않는다 —
이미 지키고 있는 규칙이다).

### 4-3. 밀도

- **한 문장 = 한 정보.** 조건·예외가 둘을 넘으면 화면이 아니라 도움말감이다.
- **— 대시는 화면 문구에서 자제한다** (문서 전용 습관 — 화면 문구에 아직 많다).
  화면에서는 문장을 끊거나 괄호 보충 1회로 대신한다. 기존 문구는 전개 단계에서 정리하되
  기계 규칙으로는 막지 않는다(정당한 쓰임도 있다).
  세는 법: `sed -nE 's/.*<string[^>]*>(.*)<\/string>.*/\1/p' app/src/main/res/values/strings.xml | grep -c '—'`
  — 종전에 적혀 있던 "108회"는 **처음부터 잘못 센 수**였다(주석까지 포함한 파일 전체 값이라
  화면에 나가지도 않는 대시를 세고 있었다). 값이 아니라 세는 법을 두는 이유가 이것이다.
- 괄호 보충은 문장당 1회까지.

### 4-4. 다른 화면 개념을 데려올 때

다른 화면의 개념(예: 연표의 **표준연도**)을 언급하면 반드시 반 문장의 정박을 붙인다 —
"표준연도(연표에서 정하는 '작중 현재' 연도)". 정박 없이는 그 화면에 가 본 적 없는
사용자에게 소음이다.

## 6. 표기 규칙

- **"해 주세요 / 해 보세요"** — 보조용언 띄어쓰기 통일 (R2가 감시).
  단, **한 단어로 굳은 합성동사는 붙여 쓴다**("도와주세요"·"알아보세요"·"살펴보세요" — 표준국어대사전
  표제어). R2가 이 예외 목록을 갖고 있으며(`LEXICALIZED_RE`), 늘릴 때는 표제어인지 확인할 것.
  세는 명령: `grep -c '해 주세요\|해 보세요' app/src/main/res/values/strings.xml`
  (혼재 비율을 숫자로 적어 두면 손대는 순간 낡는다 — 5-a의 교훈).
- **표준연도** — "표준 년도" 표기 혼재 발견(`linkage_rule_*` 2건). "표준연도"로 통일.
- 따옴표는 `'값'`(작은따옴표), 조사 병기는 기존 관행(`'%1$s'을(를)`) 유지.
- 숫자+단위 붙임: "3개", "15자", "88dp"(개발 문서만).

## 7. 재발 방지 — 이 문서의 본체

같은 문제가 다시 쌓이지 않게 하는 장치 4중이다. **문서만으로는 관행이 안 된다는 것이
이번 조사의 교훈이므로**(설명 한 줄 관행이 문서 없이 자생했다가 소급되지 못했다), 각 장치는
어기면 걸리는 지점을 갖는다.

| 장치 | 무엇 | 걸리는 지점 |
|---|---|---|
| **R-25 규약** (remaining_work 등재) | 화면에 노출되는 설정 스위치·섹션에는 목적문 한 줄("무엇이 어디서 어떻게")이 붙는다 | 새 기능 체크리스트 7(아래) + 리뷰 |
| **`tools/check_text_style.sh`** | 해요체·붙여쓰기·금지 용어를 기준선 대비 검사 — **새 위반은 즉시 실패** | 검증 규약에 편입 (check_resources와 나란히) |
| **CLAUDE.md 새 기능 체크리스트 7 "텍스트"** | 기능 검증 항목에 텍스트를 정식 편입 | 모든 기능 작업의 체크리스트 |
| **`KT_USER_FACING` 등재 규칙** | 코드 하드코딩 사용자 문구가 생기는 파일은 검사 목록에 등재 | 스크립트 주석 + 리뷰 — **이 장치는 두 번 실패했다**(전개 4단계 `StatsDataProvider` · 5단계 `FieldEditDialog`). 사람 기억에 맡기는 유일한 항목이라 그렇다. 근본 해결은 **한국어 리터럴을 `strings.xml`로 옮기는 것** — 옮기면 등재 없이도 검사된다. 미등재 파일을 훑는 명령은 스크립트 주석에 있다 |

기준선 운영: 착수 시 59건이었고 **전개 5단계에서 0건에 도달했다**(2026.07.30 — 단계별 내역은
10장). 줄인 즉시 `--rebaseline`으로 동결한다(재유입 방지).
**기준선이 늘어나는 갱신은 금지** — 새 문구는 처음부터 규칙대로 쓴다.
이제 기준선은 **0바이트**이므로, 파일이 비어 있지 않다면 그 자체가 미해결분의 존재를 뜻한다.

> **기준선 0은 "위반 없음"의 증명이 아니라 "그 규칙이 잡은 것이 없음"이다.**
> 전개 2단계가 R1에서 실제 사례를 만났다 — `볼게요|할게요`가 어간 열거식이라 저장소 전체에서
> 0건을 잡는 동안 `알려드릴게요`가 통과했다. **규칙을 믿기 전에 그 규칙이 무엇을 잡고 있는지
> 한 번 세어 볼 것**(0건이면 규칙이 좁은 것인지 정말 깨끗한 것인지 구분되지 않는다).
>
> **전개 3단계가 R2에서 같은 것을 확인했다 — 예고가 맞았다.** `해주세요` 계열 일곱 개만
> 열거해 `가져와주세요`·`비워두세요`·`적어주세요` 세 건이 통과하고 있었다. 어간 열거를
> **연결어미 + 보조용언이라는 구조**로 바꿨다. R3는 표1과 정확히 일치해 구멍이 없었다.
>
> **검사기가 무엇을 세는지도 함께 의심할 것.** R2·R3와 별개로 두 가지가 더 나왔다.
> ① 스크립트가 "주석 제외"라고 적어 두고도 실제로는 걸러내지 않아, 따옴표를 품은 주석
> (`"파싱은 되지만 소비처가 못 읽는"`)이 **화면에 나가지도 않는데 기준선에 위반으로 앉아**
> 잔여 건수를 부풀리고 있었다. **주석이 약속한 것을 코드가 하는지 보라.**
> ② 한글 대괄호 표현식은 로케일에 따라 **글자가 아니라 바이트로** 매칭된다 —
> 자기 재공격에서 `[아어여와워해]보세요`가 '살펴보세요'를 잡았다. 새 규칙은 교체(`|`)로 적고,
> 로케일은 스크립트가 `C`로 고정한다(`C.UTF-8`로 올리면 `[가-힣]`이 콜레이션 오류를 낸다).

#### H14 — 필드 데이터 라이브러리 (P4·U-5, 2026.07.30 승인·등재)

**착수 근거:** 값 라이브러리 큐레이션 0/482, 사유는 "있는 줄 몰랐다"(실사용 대조 §7 Q2).
진입점은 이번에 넷이 됐으나(필드 편집 다이얼로그 · 필드 관리 툴바 · 분석 탭 카드 · 어시스턴트),
**도착한 뒤에 무엇을 하는 곳인지 말하는 자리가 없다.** 상시 노출 목적문은 이미 넣었고
(`purpose_field_library_home`), 그보다 긴 설명이 이 초안이다.

**형태는 H13과 같은 계열이다** — 스위치 하나가 아니라 화면 전체를 설명하므로 절이 나뉜다.
읽는 순서도 H13을 따랐다: ① 무엇을 하는 곳인가 → ② 무엇을 정할 수 있는가 →
③ 몰라서 당황할 것.

**H14. 필드 데이터 라이브러리** — 필드에 입력된 값이 모이는 곳입니다. 값마다 보이는 이름과
같은 뜻의 다른 표기를 정해 두면, 앱 곳곳이 그것을 함께 씁니다.

① 값은 저절로 모입니다. 캐릭터·사건·작품에 값을 저장하면 그 필드의 목록에 들어갑니다.
② 목록에서 값을 고르면 표시 라벨·별칭·카테고리·설명·숨김을 정할 수 있습니다.
③ 정리한 결과는 입력 자동완성·통계·검색·AI 추천이 함께 씁니다.

**무엇을 정할 수 있나**
· 표시 라벨 — 통계와 카드에 보일 이름입니다. 저장된 값은 그대로 두고 보이는 이름만 바꿉니다.
· 별칭 — 같은 뜻의 다른 표기입니다. '서울'에 '서울시'를 별칭으로 두면 검색과 통계가 둘을
  하나로 셉니다.
· 카테고리 — 값을 묶는 이름입니다. 통계가 이 묶음으로도 셉니다.
· 숨김 — 입력 제안에서만 뺍니다. 통계에는 그대로 들어갑니다.
· 입력 모드 — 이 필드에 자유롭게 쓰게 할지, 목록에 있는 값만 받을지 정합니다.

**알아 두면 좋은 것**
· 값 이름을 바꾸면 캐릭터에 저장된 값까지 함께 바뀝니다. 몇 건이 바뀌는지 먼저 보여 줍니다.
· 값을 지울 때 '항목만 삭제'는 목록에서만 지웁니다. 캐릭터가 그 값을 계속 쓰고 있으면
  다시 모입니다.
· '미사용 자동수집 정리'는 아무도 쓰지 않는 값만 지웁니다. 라벨·별칭·설명·카테고리를 적어 둔
  값은 남습니다.
· 값이 많으면 엑셀이 빠릅니다. 내보낸 파일의 '필드 데이터' 시트에서 표시 라벨·별칭·카테고리를
  채워 다시 가져오면 그대로 반영됩니다.

**등재 결과:** `HelpDialog.Topic.FIELD_LIBRARY` + `help_field_library_title`·
`help_field_library_body` + 라이브러리 홈 툴바의 `?`(`menu_field_library_home.xml`).
승인 시각은 이 세션이고 초안과 본문은 **한 글자도 다르지 않다**(고칠 것이 없다는 회신).

> **H13(정리 폴더)만 형태가 다르다.** H1~H12는 필드 편집의 스위치 하나를 설명하는 2~3문장인데,
> H13은 **기능 전체의 사용법**이라 절이 나뉜다. 길이를 맞추려고 쪼개면 "폴더에 넣으면 무슨 일이
> 일어나는가"라는 한 질문이 여러 창으로 흩어진다 — 이 도움말은 한 번 읽고 마는 종류라
> 한 자리에 모으는 편이 낫다(사용자 요청: "사용자 친화적 문법으로 도움말").
>
> 대신 **읽는 순서를 설계했다**: ① 무엇을 하는 기능인가(3단계) → ② 어느 폴더에 넣으면
> 어떻게 되는가(지시표) → ③ 몰라서 당황할 것(삭제·되살아남·코드·묶음).
> 내부 용어(토큰·링크 그룹·배정)는 쓰지 않고 사용자가 보는 것으로만 말한다.

**H13. 정리 폴더** — 앱의 이미지를 폴더로 꺼내 파일 탐색기에서 정리한 뒤, 그 결과를 앱에
되돌리는 기능입니다.

① 내보내기 — 이미지가 캐릭터별 폴더로 나갑니다.
② 파일 탐색기에서 정리 — 파일을 원하는 폴더로 옮기거나 새 이미지를 넣습니다.
③ 받아오기 — 폴더 모양대로 앱에 반영됩니다.

**어느 폴더에 넣느냐가 곧 지시입니다.**
· 캐릭터 이름 폴더 → 그 캐릭터에 배정됩니다. 없던 이미지를 넣어도 바로 배정됩니다.
· 그 밖의 이름 폴더 → 배정 없이 들어오고, 같은 폴더에 있는 것끼리 묶입니다.
· 정리 폴더 바로 아래, 또는 `_미배정` 바로 아래 → 배정과 묶음이 모두 풀립니다.
· `_공유` → 여러 캐릭터가 함께 쓰는 이미지입니다. 옮겨도 반영하지 않고 알리기만 합니다.
· `_처리됨` → 반영을 마친 파일을 앱이 옮겨 두는 곳입니다. 건드리지 않아도 됩니다.

**알아 두면 좋은 것**
· 폴더에서 파일을 지워도 앱의 이미지는 지워지지 않습니다. 폴더에 있는 것만 반영합니다.
· 반대로 앱에서 지운 이미지의 사본이 폴더에 남아 있으면 다시 들어옵니다.
· 파일 이름 끝의 영문·숫자는 지우지 마세요. 그것으로 원래 이미지를 알아봅니다.
· 같은 이름의 캐릭터가 있으면 폴더 이름 뒤에 코드가 붙습니다(예: 홍길동#a1b2c3d4e5f60718).
  그 코드도 지우지 마세요. 지우면 어느 쪽인지 물어봅니다.
· 묶인 이미지 중 하나만 다른 폴더로 옮기면 묶음이 나뉘지 않고 두 묶음이 합쳐집니다.
  나누려면 이미지 탭에서 하세요.
· 반영하기 전에 무엇이 바뀌는지 먼저 보여 줍니다. 그때 취소할 수 있습니다.

**H1. 필드 키** — 필드를 구분하는 영문 이름입니다. 엑셀의 열 이름과 계산 필드 수식
`field('키')`에서 이 이름을 씁니다. 같은 세계관 안에서 겹칠 수 없습니다. 나중에 바꾸면
수식과 이력은 자동으로 따라 바뀝니다.

**H2. 표시 형식** — 값을 어떻게 보여줄지 정합니다. '기본'은 한 줄, '여러 줄'은 긴 글
그대로, '콤마 구분 목록'은 쉼표로 나눈 값을 칩이나 글머리표로 하나씩 보여줍니다.
콤마 목록으로 두면 통계도 값을 하나씩 나눠 셉니다.

**H3. 서술형 여부** — 이 필드가 긴 글인지 짧은 값인지 정합니다. 서술형이면 ✨ AI가 초안
쓰기·이어쓰기·다듬기를 돕고, 짧은 값이면 값 추천을 받습니다. '자동'은 표시 형식이
'여러 줄'일 때 서술형으로 봅니다.

**H4. 시스템 연동** — 필드 값을 앱 기능과 연결합니다. 예를 들어 '나이'로 연동하면
표준연도(연표에서 정하는 '작중 현재' 연도)가 바뀔 때 나이나 출생연도가 자동으로 다시
계산되고, '생일'로 연동하면 생일 알림과 오늘의 캐릭터에 쓰입니다. 연동 규칙에서는 표준연도가
바뀔 때 나이와 출생연도 중 무엇을 기준으로 삼을지 고릅니다.

**H5. 구조화 입력** — 한 필드를 여러 칸으로 나눠 받습니다. 예를 들어 신체 사이즈를
B·W·H 세 칸으로 나누면, 입력은 칸별로 하고 저장은 'B-W-H'처럼 한 값으로 합쳐집니다.
칸 사이를 잇는 문자(기본 '-')도 바꿀 수 있습니다.

**H6. 상위 % 표시** — 숫자 필드에서 이 캐릭터가 어디쯤인지 보여줍니다. 예를 들어 키가
상위 12%라면 캐릭터 상세의 값 옆에 함께 표시됩니다. 비교 범위는 같은 작품 또는 같은
세계관 중에서 고릅니다.

**H7. 랜덤 생성** — 입력 폼에 🎲 버튼을 더합니다. 숫자는 최솟값~최댓값 사이에서,
선택형·등급은 보기 중에서 무작위로 뽑습니다. 값을 정하기 어려울 때 초안으로 쓰고,
마음에 안 들면 다시 누르면 됩니다.
