## 2. 검증 환경 (Android 빌드 불가)

`dl.google.com`이 차단되어 `./gradlew`는 무엇을 하든 실패한다. 구축 절차와 필요한 jar 목록은
`docs/excel_roundtrip_audit_2026-07.md` 3장 그대로이며 이번 세션에서도 그대로 재현됐다.

```
JARS_DIR=/path/to/jars tools/setup_jvm_env.sh        # jar 수집 + androidx 스텁 (세션마다 1회)
JARS_DIR=/path/to/jars tools/run_jvm_tests.sh        # 순수 JVM 단위 테스트 — 현재 981건 통과
# 차분 컴파일 — 출력 파일 경로가 **필수 인자**다(빼면 unbound variable로 죽는다).
# 기준선은 HEAD 워크트리에서 따로 뜬다. 줄 번호는 스크립트가 지우므로 comm으로 바로 비교한다.
git worktree add /tmp/head-wt HEAD
REPO=/tmp/head-wt JARS_DIR=/path/to/jars tools/differential_compile.sh /tmp/base.txt
JARS_DIR=/path/to/jars tools/differential_compile.sh /tmp/cur.txt
comm -13 /tmp/base.txt /tmp/cur.txt                   # 신규 오류만 남는다
python3 tools/verify_room_migration.py                # 41→42 하네스 35건
python3 tools/verify_room_migration_43.py             # 42→43 하네스 49건 (B-1에서 추가)
python3 tools/verify_room_migration_44.py             # 43→44 하네스 25건 (자동 링크)
python3 tools/verify_reset_coverage.py                # 리셋 커버리지 30건 (S-13에서 추가)
tools/check_resources.sh                              # strings.xml 중복 name 등
tools/check_text_style.sh                             # 화면 문구 스타일 — 기준선 대비 새 위반 시 실패
tools/check_dialog_validation.sh                       # 다이얼로그 검증이 입력을 유실하지 않는가 (R-27)
```

**`tools/setup_jvm_env.sh`가 이 준비를 전부 한다**(jar 수집 + 스텁 컴파일). 세션마다 스크래치패드가
비므로 매 세션 1회 돌린다. 스텁에서 막히기 쉬운 세 지점(ForeignKey 상수 / @Ignore의 PROPERTY_GETTER /
@Relation.associateBy가 KClass여야 하고 LiveData는 `open var value` 하나여야 함)은 스크립트 주석에 있다.

`JARS_DIR`에는 `tools/setup_jvm_env.sh`가 받는 jar(목록 원문은 위 문단이 가리키는
`docs/excel_roundtrip_audit_2026-07.md` 3장)과 함께 **androidx 스텁을 컴파일한 `out-room/`** 이 있어야 한다
(`androidx.room` 어노테이션 + `androidx.lifecycle.LiveData`). `@Ignore`는
`AnnotationTarget.PROPERTY_GETTER`까지 받아야 `Character.displayName`이 컴파일된다.

**차분 컴파일이 못 보는 것을 보는 방법(이번 세션에서 가장 값졌다):** Room 런타임이 없는
차분 컴파일은 DAO 반환 타입을 해석하지 못해 그 위의 모든 멤버 접근이 "unresolved"로 뜬다.
`TrashRepository` 같은 신규 대형 파일은 **작은 스텁을 만들어 실제 클래스패스로 컴파일**하면
진짜 타입 검사가 된다 — `AppDatabase`(DAO 접근자만), `RoomDatabase`+`withTransaction`,
`android.util.Log`, `GsonTypes`/`ImageOwnershipGuard`/`FieldValueLibraryRepository` 스텁이면
`data/model` + `data/dao` + 대상 저장소가 통째로 컴파일된다(이번엔 216 클래스, 오류 0).
이 방법으로 차분 컴파일이 "새 오류"로 표시한 40여 건이 전부 노이즈임을 증명했다.

**하네스 전용 스텁은 이제 저장소 안에 있다(`tools/jvm-stubs/` — 현재 셋. `ls tools/jvm-stubs/`).**
`StatsHarnessStubs.kt`가 `NovelCharacterApp`과 그것이 노출하는 DAO·저장소의 **시그니처만**
선언하고, `AndroidLogStub.kt`가 `android.util.Log` 자리를, `AiServiceStub.kt`가 AI 순수 로직
(프롬프트 조립·파싱) 컴파일에 필요한 자리를 채운다. Gradle 소스셋 밖이라 실제 빌드와
충돌하지 않는다. `loadSnapshot`이 부르는 메서드가 사라지거나 시그니처가 바뀌면
**하네스 컴파일이 깨진다 — 그것이 목적이다.**

`StatsDataProvider`가 이 방식으로 실행 검증 대상이 됐다(생성자 대신 `loadSnapshot(app)`이
앱을 받는다). 앱 의존이 로딩 함수 하나뿐인 대형 계산기는 같은 방법으로 옮겨올 수 있다.

검증 요령(항목이 늘어나므로 수를 적지 않는다):

- **줄 번호는 이제 스크립트가 지운다** — 두 출력을 `comm -13`으로 바로 비교하면 된다.
  (2026.07.30까지 스크립트 안의 정규화 `sed`가 **콜론 하나가 빠져 한 번도 매칭되지 않았고**,
  그래서 줄 번호가 그대로 남았다. 2줄만 삽입해도 그 아래 오류가 전부 '신규'로 보여
  실제로 **신규 311건**이 나온 적이 있다 — 정규화하면 0건이었다. 도구가 시키는 절차를
  줄이면 도구가 거짓말을 한다.)
- **그래도 '새 것'이 무더기로 나오면 경로까지 지우고 메시지 단위로 비교하라.** 신규/대폭 수정
  파일은 경로가 키에 섞여 모든 오류가 새 것으로 보인다:
  `sed -E 's/^[^:]+: (error: .*)$/\1/'`로 경로를 지우고 `comm -13`한다.
  `unresolved reference 'let'`, `should be called only from a coroutine` 등은
  기준선에 수십~수백 건 있는 노이즈 클래스다.
- **차분 컴파일이 못 보는 구문은 떼어내 실제 클래스패스로 컴파일하라.** 이번에는
  `withTransaction` 람다의 캡처 var 대입 + 바깥 elvis, suspend 람다를 받는 제네릭 헬퍼,
  루프 안 조건부 `continue`를 이 방법으로 확인했다(참고: Kotlin 2.0에서 **inline 람다 안의
  `continue`는 컴파일 오류**다 — `?: run { ... continue }` 형태를 쓰지 말 것).
- **POI 제약은 실제 POI로 확인하라.** 규칙만 검사하는 테스트는 "내보내기가 예외로 죽는" 경로를
  잡지 못한다. `SheetNameAssignmentTest`가 적대적 이름 20개로 실제 `createSheet`를 돌린다.

### 3-5. 우선순위 1 산출물(B-2·B-21·B-3)의 실기기 확인 — ⬜ 미검증

1. **편집 백업 되돌리기.** 필드값·태그·세력 소속이 있는 캐릭터를 편집 화면에서 다른 세계관의
   작품으로 옮겨 저장한다("보관했습니다" 스낵바 = 편집 백업 생성). 그 뒤 **태그를 하나 더 붙이고
   관계를 하나 만든다.** 휴지통에서 그 항목의 '복원'을 누르면 "되돌리는 것입니다 — 덮어써지는
   갈래 목록" 동의 다이얼로그가 떠야 하고, 진행하면 **사본이 생기지 않고** 원본이 옛 세계관
   상태로 돌아가야 한다. **나중에 붙인 태그와 관계는 남아 있어야 한다**(교체 범위 밖).
   휴지통에는 "덮기 직전 백업"이 새로 생겨 있어야 하고, 그것을 복원하면 다시 이동 후 상태로
   돌아와야 한다(왕복).
2. **엑셀 임포트의 세계관 이동 백업.** 캐릭터의 작품을 다른 세계관 작품으로 바꾼 엑셀을
   가져온다(경고: "세계관 이동 감지 — 휴지통에 스냅샷 보관"). 휴지통에서 그 항목이 **'편집 직전
   백업'으로 표시**되고(종전에는 삭제로 표시), 복원 시 1번과 같은 되돌리기 동의가 떠야 한다.
   같은 임포트가 '엑셀에 없는 항목 삭제'도 했다면 삭제 묶음 머리글에 편집 백업이 **섞여 있지
   않아야** 하고, 삭제 묶음의 '전체 복원'이 편집 백업을 건드리지 않아야 한다.
3. **상태변화 중복 차단.** 상태변화 이력을 삭제 → 같은 캐릭터·같은 필드로 새 이력을 만든 뒤
   휴지통에서 복원한다. "같은 이력이 이미 있어 복원하지 않았습니다" 다이얼로그가 뜨고 **항목이
   휴지통에 남아야** 한다(종전에는 사본이 생겼다). 기존 이력을 지운 뒤 다시 복원하면 성공해야 한다.
4. **이름 은행 링크 왕복.** 이름 은행에서 이름을 골라 캐릭터를 만들고(사용 표시 켜짐), 캐릭터를
   삭제한다(사용 표시 풀림 확인). 휴지통에서 복원하면 **사용 표시가 그 캐릭터로 되돌아와야** 한다.
   반대로: 삭제 후 그 이름을 **다른 캐릭터에 배정**한 뒤 복원하면 빼앗지 않고 "이름 은행 사용
   표시 1개" 유실 고지가 떠야 한다.
5. **사본 복원의 무경고.** 캐릭터를 지우고 같은 code가 살아나게 엑셀 덮어쓰기로 되살린 뒤
   휴지통에서 복원한다(사본 생성 경로). 결과에 "이름 은행 사용 표시 N개" 유실이 **뜨지 않아야**
   한다 — 원본이 링크를 쥐고 있는 것은 유실이 아니다.

### 3-6. 우선순위 2 산출물(B-4·B-5)의 실기기 확인 — ⬜ 미검증

> 이 세션은 Android 빌드가 불가능하므로 집계 규칙만 순수 JVM으로 실행 검증했다.
> **화면 동작은 사용자 확인이 필요하다.**

**B-4 — 교차분석 사건 축**

1. **사건 축이 실제로 표를 만든다.** 사건 필드를 2개 이상 만들고(예: '회차' TEXT, '사건 유형'
   SELECT — 둘 다 통계 포함 켜기) 사건 여러 건에 값을 채운다. 통계 → 필드 탐색 → '교차 분석'
   → **'집계 축'에서 '사건 필드'** 선택 → 두 필드를 골라 실행. 표가 나오고 캡션 첫 줄이
   **"셀 값 = 해당 조합을 가진 사건 수"** 여야 한다. 제목 앞에 "사건 ·"이 붙는다.
   *(종전 결함: 사건 필드를 고르고 실행하면 아무 일도 일어나지 않았다.)*
2. **캐릭터 축은 종전대로.** 축을 '캐릭터 필드'로 두고 실행하면 예전과 같은 표가 나오고
   캡션은 "셀 값 = 해당 조합을 가진 캐릭터 수"여야 한다.
3. **축이 하나뿐이면 선택기가 숨는다.** 사건 필드가 0~1개인 세계관에서는 '집계 축' 줄이
   보이지 않고 캐릭터 필드만 실린다. 양쪽 다 2개 미만이면 "같은 축의 ... 2개 이상 필요합니다"
   안내가 뜬다.
4. **필터도 같은 축.** 사건 축에서 필터 필드 스피너에 **캐릭터 필드가 실리지 않아야** 한다.
   필터를 걸면 캡션이 "(N/M건)"으로 나온다(캐릭터 축은 "명").
5. **미분류 캐릭터가 표에 남는다.** 캐릭터의 작품을 '없음'으로 두고 필드값을 채운 뒤 캐릭터 축
   교차분석을 실행하면 그 캐릭터가 **표에 포함**돼야 한다(자기 재공격이 잡은 결함).
6. **세계관 통합 고지.** 같은 필드 key를 쓰는 세계관이 2개 이상이면 캡션에
   "세계관 N개의 같은 필드를 합산했습니다"가 나온다.

**B-5 — 연표 카드 사건 필드값**

7. **값이 목록에 보인다.** 사건에 필드값을 채우고 연표로 돌아오면 카드에 `필드명: 값` 줄이
   보여야 한다(사건을 열지 않고). 값을 지우면 줄도 사라진다.
8. **표시 끄기.** 필드 관리 → 사건 필드 탭 → 필드 편집 → **'목록 카드에 값 표시'** 를 끄면
   그 필드만 카드에서 사라진다(다른 필드는 남는다). 캐릭터 필드 편집 화면에는 이 스위치가
   **보이지 않아야** 한다.
9. **초과 개수 고지.** 한 사건에 값 있는 표시 필드를 5개 이상 만들면 카드에 4줄까지 보이고
   그 아래 **"+N개 더 (열어서 확인)"** 가 떠야 한다.
10. **묶음 보기에는 안 나온다.** 줌을 낮춰(10년/100년 묶음) 머리글 카드가 되면 필드값 줄이
    보이지 않아야 한다(재활용된 뷰의 잔상 확인).
11. **재정렬이 안 깨진다.** 연표 재정렬 모드에서 사건을 끌어 옮긴 뒤 모드를 끄면 **끌어 옮긴
    순서가 저장**돼야 한다(자기 재공격이 잡은 결함 — 요약 조회가 끼어들어 순서를 지웠다).

### 3-7. 이번 세션 산출물(S-6·S-12)의 실기기 확인 — ⬜ 미검증

> 집계·병합 규칙은 순수 JVM으로 실행 검증했다(481건). **화면 동작은 사용자 확인이 필요하다.**

**S-6 — 사건 필드값 보호**

1. **작품 소실 사건의 편집이 값을 지우지 않는다.** 사건 필드값(회차 등)을 채운 사건이 있는
   작품을 삭제한다(사건은 남는다). 그 사건을 연표에서 열면 **필드 입력란이 여전히 보이고
   기존 값이 채워져 있어야 한다**(세계관 폴백). 설명만 고치고 저장 → 다시 열면 필드값이
   그대로여야 한다. *(종전: 열면 필드란이 사라지고, 저장하면 값 전량이 소리 없이 삭제됐다.)*
2. **작품 체크 해제 저장이 값을 지우지 않는다.** 정상 사건을 열어 작품 체크를 전부 해제하고
   저장한다. 필드 섹션은 폴백으로 계속 보이므로 값이 그대로 저장되고, 연표 필터에서 그
   세계관을 골랐을 때 사건이 **여전히 그 세계관에 남아 있어야 한다**(universeId 보존 —
   종전에는 세계관 연결도 말없이 끊겼다).
3. **다른 세계관으로 이동 시 보존 고지.** 사건을 세계관 X 작품에서 세계관 Y 작품으로 바꿔
   저장한다. X 필드값은 지워지지 않고 **"화면에 없는 사건 필드값 N개는 지우지 않고
   보관했습니다"** Toast가 떠야 하며, 작업 이력에도 같은 줄이 남아야 한다. 작품을 X로
   되돌리면 값이 다시 보여야 한다(문구의 교정 경로 확인).
4. **빠른 저장(로딩 미완 창).** 필드가 많은 세계관의 사건을 열자마자(필드 섹션이 그려지기
   전에) 즉시 저장을 누른다. 저장 후 다시 열면 필드값이 **하나도 사라지지 않아야 한다.**
   4-1. **회전 변형(재공격 F1·F3).** ① 필드값 있는 사건을 열자마자 즉시 회전 → 폼에 기존
   값이 채워져 렌더되어야 한다(공란 렌더면 결함). ② 사건을 열어 필드값을 고치고 → 회전 →
   재생성 직후 곧바로 저장 → 다시 열면 **고친 값이 저장돼 있어야** 하고, "보관했습니다"
   토스트는 뜨지 않아야 한다.
5. **비움 의도는 존중된다.** 사건을 열어 필드값 하나를 지우고 저장하면 그 값만 삭제되고
   보존 고지는 뜨지 않아야 한다(커버 안의 비움은 보존이 아니라 삭제다).
6. **연도 이동 경로도 동일.** 3번을 연도까지 바꿔 저장해 '다른 사건도 함께 이동' 다이얼로그를
   거쳐도 필드값 보존·고지가 같아야 한다.
7. **캐릭터 화면 경로도 동일.** 1~3을 캐릭터 상세의 사건 목록에서 열어 반복한다(저장 경로가
   CharacterViewModel로 분리돼 있다 — 한쪽만 고쳐졌는지 확인).

**S-12 — 관계변화 다이얼로그**

8. **연도 공란 저장이 입력을 버리지 않는다.** 관계 변화 추가에서 유형·설명·강도·사건 연결을
   채우고 연도만 비운 채 저장을 누른다. **다이얼로그가 닫히지 않고** 연도 입력란에
   "연도를 입력해주세요" 인라인 오류가 떠야 하며, 입력값이 전부 남아 있어야 한다.
   연도를 채우면 오류가 사라지고 저장이 되어야 한다. *(종전: 다이얼로그가 닫히며 전부 소멸.)*
9. **편집 다이얼로그도 동일 + 삭제·취소는 종전대로.** 기존 관계 변화를 열어 연도를 지우고
   저장 → 같은 인라인 오류·유지. '삭제'와 '취소' 버튼은 검증 없이 종전처럼 즉시 동작해야 한다.

### 3-8. 이번 세션 산출물(S-5 월드패키지)의 실기기 확인 — ⬜ 미검증

> 파서·코드 정책·판별기·세력 관계 역해석은 순수 JVM으로 실행 검증했고(509건), 임포터·내보내기
> 본체는 실클래스패스 스텁 컴파일로 타입 검사만 했다. **DB 삽입·다이얼로그·이미지 복원의
> 실동작은 사용자 확인이 필요하다.**

1. **왕복 기본.** 필드값·사건(사건 필드값 포함)·세력(세력 간 관계 포함)·태그·관계·상태변화·
   이미지가 있는 세계관을 설정 → 세계관 패키지로 내보낸다. 그 .ncworld를 설정의 *엑셀에서
   가져오기*로 고른다. *(종전: "가져오기에 실패했습니다"만 떴다.)* 이제 충돌 다이얼로그
   (같은 세계관이 있으므로)가 떠야 한다. **'새로 생성'**을 고르면 "이름 (2)" 세계관이 생기고
   캐릭터·필드값·사건·사건 필드값·세력·세력 간 관계·관계·상태변화·태그·이미지가 전부
   원본과 같아야 한다. 결과 다이얼로그에 "코드를 재발급한 항목 N건" 안내가 떠야 한다.
2. **덮어쓰기.** 같은 파일을 다시 가져와 **'덮어쓰기'** 선택 → "캐릭터 N명…휴지통에 보관"
   확인 다이얼로그(R-4) → 진행하면 기존 세계관이 휴지통에 가고 패키지 내용으로 교체된다.
   휴지통에서 그 삭제 묶음을 '전체 복원'하면 사본으로 되살아나야 한다(원본 자리는 새 임포트).
3. **건너뛰기.** 같은 파일 → '건너뛰기' → 아무 변화 없어야 한다.
4. **값 라이브러리 큐레이션 왕복.** 필드 하나에 표시 라벨·별칭·카테고리를 큐레이션하고
   내보내기 → 삭제 없이 '새로 생성'으로 가져오기 → 새 세계관의 값 라이브러리에 라벨·별칭이
   그대로 있어야 한다. *(종전: 값 라이브러리 자체가 패키지에 없었다.)*
5. **이름 은행 링크.** 이름 은행에서 고른 이름을 쓰는 캐릭터를 내보내고, 캐릭터를 지운 뒤
   (이름 사용 표시 풀림) 가져오기 → 그 이름의 사용 표시가 **가져온 캐릭터로 이어져야** 한다.
   다른 캐릭터가 그 이름을 쓰는 중이면 빼앗지 않고 "사용 표시 N건은 다른 캐릭터가 사용 중"
   안내가 떠야 한다. 은행에 없던 이름은 새로 등록된다(패키지 캐릭터가 쓰는 이름만).
6. **이미지 미포함 패키지.** '이미지 포함'을 끄고 내보낸 파일을 **다른 기기(또는 앱 데이터
   삭제 후)**에서 가져오면 "이미지 미포함 패키지 — 이미지 연결 N개 제외" 안내가 떠야 한다.
   같은 기기에서 가져오면 원 파일이 살아 있으므로 이미지가 그대로 보여야 한다.
7. **지원하지 않는 ZIP.** 아무 ZIP(사진 압축본 등)을 가져오기로 고르면 "지원하지 않는 ZIP
   파일입니다"가 떠야 한다. *(종전: "가져오기에 실패했습니다".)* 엑셀 백업 ZIP과 .xlsx는
   종전대로 동작해야 한다(회귀 확인).
8. **동명 세계관 여럿.** 같은 이름의 세계관을 두 개 만든 상태에서 그 이름의 패키지(코드는
   다른 것 — 다른 기기에서 만든 파일이거나, 내보낸 뒤 두 세계관을 새로 만든 경우)를 가져오면
   충돌 다이얼로그에 **덮어쓰기 선택지가 없어야** 한다(대상 모호).

### 3-9. 이번 세션 산출물(S-7·S-8·S-9·S-19 통계 드릴다운)의 실기기 확인 — ⬜ 미검증

> 집계 규칙은 순수 JVM으로 실행 검증했다(528건 — 머지 조회·사건 드릴다운·계산 필드 하위 그룹·
> 캐릭터 축 CALCULATED 교차분석). **시트 전환·차트 탭·연표 이동의 실동작은 사용자 확인이 필요하다.**
>
> 준비물: **세계관 2개**(A·B)에 **같은 이름·같은 타입의 필드**(예: '직업' TEXT)를 각각 만들고
> 양쪽에 같은 값(예: '검사')을 가진 캐릭터를 여러 명 둔다. 통계 화면의 작품 필터는 **전체**로 둔다.

1. **머지 드릴다운(S-7).** 통계 → 필드 탐색에서 '직업' 카드를 찾는다(세계관 A·B가
   **한 장**으로 합쳐져 있어야 한다). '검사' 조각의 숫자를 확인하고 **탭한다.**
   → 시트의 "N명의 캐릭터"가 **차트 숫자와 같아야** 하고 목록에 A·B 양쪽 캐릭터가 모두 있어야
   한다. *(종전: A세계관 캐릭터만 나왔다.)*
2. **하위 그룹 머지(S-7·S-19).** 그 시트에서 **'이 그룹의 다른 필드 분포 보기'** →
   필드 목록에 **'직업'이 없어야** 하고(형제 세계관 def까지 함께 제외), 같은 이름의 필드가
   **중복으로 나열되지 않아야** 한다. 다른 필드를 고르면 A·B 양쪽 값이 합산돼 나온다.
3. **계산 필드 하위 그룹(S-19).** 수식 필드(CALCULATED, 예: `field('힘') * 2`)를 만들고
   2번의 목록에서 그것을 고른다. → **분포가 실제로 나와야 한다.**
   *(종전: 항상 '데이터가 없습니다'.)*
4. **캐릭터 축 교차분석 + 계산 필드(S-8).** 필드 탐색 화면 상단 **교차 분석** →
   축을 **캐릭터 필드**로 두고 축1에 그 수식 필드, 축2에 아무 필드나 골라 실행한다.
   → **표가 실제로 그려져야 한다.** *(종전: 제목만 있고 표가 비었으며 아무 안내도 없었다.)*
   축2·필터에 수식 필드를 놓아도 같아야 한다.
5. **빈 표의 고지(S-8 방어선).** 교차분석의 필터 값에 아무 캐릭터도 갖지 않은 값
   (예: `존재하지않는값`)을 넣고 실행한다. → 표 자리에 **"조건에 맞는 캐릭터가 없어…"**
   안내가 떠야 한다. *(종전: 아무것도 그려지지 않고 조용했다.)* 사건 축이면 "…사건이 없어…"다.
6. **사건 필드 드릴다운(S-9).** 사건에 커스텀 필드(예: '사건 유형')를 만들어 값을 채우고
   통계 → 필드 탐색에서 **'사건 · …'** 접두사가 붙은 카드를 찾는다. 조각을 **탭한다.**
   → **"N건의 사건"**과 사건 목록(설명 + 날짜 · 값)이 나와야 한다.
   *(종전: '0명의 캐릭터'와 빈 목록.)*
7. **사건 행 탭 → 연표.** 6번 목록의 행을 탭한다. → 연표 탭이 열리고 **그 사건의 연도로
   이동**해 있어야 한다(전역 검색에서 사건을 탭한 것과 같은 동작).
8. **사건 하위 그룹.** 6번 시트의 **'이 사건들의 다른 필드 분포 보기'** → 사건 필드만
   나열돼야 하고(캐릭터 필드가 섞이면 안 된다), 결과가 **'건' 단위**로 표시돼야 한다.
9. **필드가 하나뿐일 때의 고지.** 사건 필드가 하나뿐인 상태에서 8번을 누르면
   **"함께 볼 다른 필드가 없습니다…"** 안내가 떠야 한다. *(종전: 아무 반응 없음.)*
10. **회귀 — 레거시 필드 분석 화면.** 통계 → (필드 분석 상세) 화면의 파이 차트 조각을 탭하면
    종전과 **똑같이** 그 필드 하나의 캐릭터 목록이 떠야 한다(이 화면은 세계관 통합을 하지
    않으므로 머지되면 오히려 틀린다).
11. **회귀 — 작품 필터.** 작품을 하나 고른 상태에서 1·6번을 반복한다. 카드가 그 세계관만
    보여주고 드릴다운도 그 범위여야 한다.

### 3-10. 이번 세션 산출물(로드맵 4 — 통계 정합성)의 실기기 확인 — ⬜ 미검증

> 순수 JVM 테스트 618건과 차분 컴파일로 계산 규칙은 고정했으나, **화면에 실제로 그렇게 그려지는지**는
> 실기기에서만 확인된다. 아래는 이번 수정이 바꾼 화면 동작 전부다.

**준비:** 세계관 2개(A·B)에 같은 이름·같은 타입의 필드(예: '성별' SELECT, '직업' TEXT)를 두고
양쪽 작품에 캐릭터를 몇 명씩 만든다. 값 종류가 12개 이상인 필드(예: '거주지')도 하나 만든다.

1. **'통계에 포함' 끄기.** 필드 편집에서 세계관 B의 '성별'만 '통계에 포함'을 끈다. 그다음 통계 →
   - 감지된 패턴 카드에 **B의 성별 관련 편중 카드가 사라져야** 한다(종전: 그대로 떴다).
   - 필드 분석 상세(레거시)의 값 분포에서도 빠져야 한다. 단 **필드 완성도 목록에는 그대로 있어야**
     한다(입력 현황은 분석이 아니다).
   - 교차분석에서 '성별'을 축으로 고르면 **A만 집계**되고, 카드의 수치와 표의 셀 합이 같아야 한다.
     "세계관 2개를 합산했습니다" 문구가 뜨지 않아야 한다.
2. **어시스턴트 연동.** 통계 → 감지된 패턴 톱니에서 '편중'을 끈 뒤 어시스턴트 화면을 연다.
   **편향 카드가 뜨지 않아야** 한다(종전: 통계에서 꺼도 어시스턴트에는 그대로 떴다).
3. **일방통행 함정.** 톱니에서 **모든 유형의 체크를 해제**하고 저장한다. 카드가 사라지지 않고
   "모든 패턴 유형이 꺼져 있습니다…" 안내와 **톱니가 그대로 남아야** 한다. 다시 켜면 복구된다.
   *(종전: 카드가 통째로 사라져 되돌릴 방법이 없었다.)*
4. **비율과 '기타'.** 값 종류가 12개 이상인 필드의 필드 카드에서
   - 표의 비율 합이 **100%**여야 하고(종전: 상위 10종만으로 100%가 되어 각 값이 부풀려졌다),
   - 표 마지막에 **'기타 N종'** 행이 있고, 파이차트에도 같은 조각이 있어야 하며,
   - **'기타' 조각을 탭하면** 잘린 값들을 가진 캐릭터 목록이 떠야 한다(0명이 아니어야 한다).
5. **BODY_SIZE 구간 드릴다운.** 신체 사이즈 필드에 값이 5명 이상 있는 상태에서
   통계 → 필드 분석 상세 → '신체 — 키' 파이의 구간 조각(예: '160~170')을 탭한다.
   **그 구간에 실제로 속한 캐릭터가 떠야** 한다. *(종전: 어떤 조각을 눌러도 항상 0명.)*
   조각의 건수와 시트의 인원 수가 같은지 확인한다.
6. **수식 필드가 모든 화면에 나온다.** CALCULATED 필드를 하나 만들고(예: `field('키') / 100`)
   - 필드 분석 상세의 **수치 요약**에 나와야 하고(종전: 통째로 없었다),
   - 통계 메인 요약의 '주요 필드 값 TOP 5'와 작품별 비교의 TOP 5에도 집계되며,
   - **순위 탭의 값과 필드 카드의 분포 값이 같은 문자열**이어야 한다(예: 둘 다 `1.75`).
7. **순위 빈도.** 표시 형식이 '콤마 구분 목록'인 TEXT 필드(예: 무기 = "검, 활")를 순위 대상으로 고른다.
   - 전원 1회 동률이 아니라 **토큰별 빈도**로 순위가 나와야 한다.
   - 같은 필드의 필드 분포 차트 수치와 순위의 회수가 **일치**해야 한다.
   - 값 라이브러리에 별칭을 등록한 필드(예: '장검' → '검')에서도 두 화면 수치가 같아야 한다.
8. **머지 카드의 톱니.** 두 세계관에 같은 필드가 있는 상태에서 필드 카드(세계관명이 안 붙은 카드)의
   톱니를 연다. **"같은 이름의 다른 세계관 필드에도 적용 (2개)"** 체크박스가 보이고 기본 켜짐이어야 한다.
   차트 종류를 바꿔 저장한 뒤 **작품 필터를 B로 바꿔** 같은 필드 카드를 본다 — 바꾼 차트 종류가
   유지돼야 한다. *(종전: 대표 def에만 저장돼 옛 설정이 되살아났다.)*
   체크를 끄고 저장하면 그 세계관만 바뀌어야 한다.
9. **오류 고지.** 작품 필터를 **로딩 중에** 연속으로 바꿔 본다. "통계를 처리하지 못했습니다
   (JobCancellationException)" 같은 토스트가 **뜨지 않아야** 한다(취소는 오류가 아니다).
   또 통계 화면을 회전하거나 다른 탭에 갔다 돌아왔을 때 **이전에 본 오류 토스트가 다시 뜨지 않아야**
   한다.
10. **회귀 — 종전 동작.** 필드 카드의 차트 조각 탭, 하위 그룹 분석, 사건 필드 카드의 조각 탭,
    교차분석 실행, 순위 탭의 정렬·필터 복원이 전부 종전대로 동작해야 한다.

### 3-11. 이번 세션 산출물(로드맵 5 — 수식 오류 가시화)의 실기기 확인 — ⬜ 미검증

**대상:** 필드 관리 → 계산 수식(CALCULATED) 필드 추가·편집.

1. **미지 함수 경고.** 수식에 `sqrt(4)`를 넣고 저장을 누른다. "수식 확인" 창이 뜨고
   **없는 함수입니다: sqrt (쓸 수 있는 함수: abs, max, min, avg, field, sum_all_grades)**가
   보여야 한다. '수정하기'를 누르면 창이 닫히되 **입력이 그대로 남아** 있어야 하고,
   '그대로 저장'을 누르면 저장돼야 한다(자율성 유지).
2. **함수 표기 오류.** `abs (field('키'))`처럼 함수 이름과 여는 괄호 **사이를 띄워** 저장한다 —
   "함수 표기가 어긋나 계산에서 빠집니다: abs"가 떠야 한다. `sum_all_grades(1)`도 같은 경고.
3. **자기참조·순환 참조.** ① 필드 A의 수식에 `field(A)`(자기 키)를 넣으면 "자기 자신(A)을
   참조합니다". ② A는 `field(B)`, B는 `field(A)`로 만들면 저장 시 **"수식이 서로 돌아옵니다:
   A → B → A"**가 떠야 한다.
4. **키 앞뒤 공백.** `field( 키 )`처럼 공백을 넣어 저장하면 "필드 키 앞뒤의 공백까지 이름으로
   읽습니다"가 떠야 한다(그대로 저장하면 값은 0으로 계산된다 — 종전과 같다).
5. **사건 필드(F-4 수리 확인).** 연표 → 사건 필드에서 CALCULATED 필드를 만들고, **사건 필드**로
   존재하는 키를 `field(키)`로 참조한다. "존재하지 않는 필드 키" 경고가 **뜨지 않아야** 한다.
   (종전에는 캐릭터 필드 목록을 보고 판단해 멀쩡한 키를 없다고 했다.) 반대로 캐릭터에만 있는
   키를 넣으면 경고가 떠야 한다.
6. **수식 안내 문구(F-6).** 수식 입력란 아래 안내에 **`avg(a,b)`가 포함**돼 있어야 한다.
7. **정상 수식은 조용하다.** `field(힘) + field(민첩) * 2`, `max(field(힘), field(민첩))`,
   `sum_all_grades()`를 저장할 때 **아무 경고도 뜨지 않아야** 한다. (이것이 무너지면 사용자가
   경고를 읽지 않게 되어 나머지 전부가 무의미해진다.)
8. **F-2의 값 변화 확인 — 회귀 위험 지점.** 기존에 쓰던 수식 필드들의 캐릭터 상세 값이
   종전과 같은지 훑어본다. **연산자가 빠진 수식**(예: `field(a) field(b)`)이 있었다면 이제
   `오류`로 표시된다 — 이는 의도된 변화이며, 그 필드를 고치면 값이 돌아온다. 정상 수식의
   값이 `오류`로 바뀐 것이 있다면 **그것은 결함이므로 보고할 것.**

### 3-12. 이번 세션 산출물(로드맵 6 스트리밍 배선 · 로드맵 7 초기화 완결)의 실기기 확인 — 🔶 일부 확인

> **가장 중요한 것은 1~3번이다.** 가져오기는 이 앱에서 회귀 반경이 가장 넓은 경로이고,
> 이번 변경은 그 경로가 읽는 **원본 구현을 갈아 끼웠다.** 순수 JVM 동치 테스트 8건이
> 두 경로가 같은 값을 낸다는 것을 실행으로 증명한다.
>
> **1번은 사용자가 실기기에서 확인해 통과했다(2026-07-29 회신).** 내보내기 정상, 왕복 결과
> "전과 같음". → **DOM 경로 회귀 없음이 실제 백업 파일로 확인됐다.** 이것이 이번 배선에서
> 가장 넓은 위험이었다(모든 기존 사용자가 타는 경로).
>
> **아직 확인되지 않은 것: 스트리밍 경로(3번).** 평소 크기 백업은 힙에서 역산한 예산 안이라
> **DOM 경로를 탄다** — 즉 1번의 통과는 스트리밍 경로를 한 번도 실행하지 않았다는 뜻이다.
> 그 경로는 여전히 JVM 동치 테스트로만 증명돼 있다.

1. ~~**작은 백업 왕복(회귀 확인 — 여기가 제일 중요하다).**~~ **✅ 통과 (2026-07-29).**
   평소 쓰던 크기의 백업을 내보낸 뒤 그대로 다시 가져오니 "전과 같음"이 나왔고 내보내기도 정상.
   이 크기는 DOM 경로라 **동작이 달라지면 안 되는** 자리였고, 달라지지 않았다.
2. **날짜 필드 확인.** 생일 등 날짜 필드가 있는 캐릭터를 내보내고 다시 들이기 →
   날짜가 숫자(예: `44000`)로 바뀌지 않는가? (배선 전 갈릴 뻔했던 바로 그 자리다.)
   *1번이 "전과 같음"이었으므로 **날짜 필드에 값이 있었다면** 이미 함께 확인된 셈이다 —
   값이 뒤집혔다면 그 캐릭터가 '변경'으로 잡혔을 것이다. 날짜 필드를 안 쓰고 있었다면 미확인.*
3. **큰 백업 복원.** 이미지가 많거나 캐릭터가 수백인 백업(가능하면 종전 128MB 근처 이상)을
   복원 → **거부되지 않고** 들어오는가? 결과 다이얼로그의 건수가 맞는가?
4. **병합 셀.** 내보낸 엑셀을 외부 편집기에서 열어 어떤 열의 셀 두어 개를 병합한 뒤 들이기 →
   병합된 값이 유실되지 않고 "병합 셀 N건" 고지가 뜨는가?
5. **초기화 — 휴지통.** 캐릭터 몇을 지워 휴지통에 넣고 → 설정 > 앱 초기화 →
   휴지통이 **비어 있는가?** (종전에는 항목이 남아 복원 가능해 보였고, 복원하면 이미지가
   깨진 캐릭터가 되살아났다.)
6. **초기화 — 나머지.** 초기화 후 작업 이력이 비었는가 · 캐릭터 탭의 저장한 목록 프리셋 칩이
   사라졌는가 · 이미지 탭이 비었는가(이미지 태그 포함).
7. **초기화 — 남는 것.** 초기화 후에도 **테마와 AI 설정(API 키·공급자)은 그대로**인가?
   (일부러 남긴다 — 지워졌다면 그것이 결함이다.)
8. **초기화 후 폴더 왕복.** 초기화 뒤 이미지 정리 폴더에 이미지를 놓고 받아오기 →
   "새 이미지"로 **잡히는가?** (지문 장부가 남아 있으면 조용히 안 잡힌다.)

### 3-13. 동명이인 폴더 지원의 실기기 확인 — ⬜ 미검증

**전제:** 같은 이름의 캐릭터를 둘 이상 만들어 두고(가능하면 작품을 다르게), 각자에게
이미지를 몇 장씩 배정해 둘 것.

1. **내보내기 — 코드 폴더가 생기는가.** 이미지 탭 > 정리용 내보내기 →
   `홍길동#a1b2c3d4e5f60718` 꼴 폴더가 **동명 캐릭터 수만큼** 생기는가?
   결과 요약에 "동명이인 제외" 문구가 **더는 뜨지 않는가?**

### 3-18. P3 전개 2단계(어시스턴트·보충 문구)의 실기기 확인 — ⬜ 미검증

### 3-19. 이미지 폴더 '기타' 서랍 + AI 태그(1-j장 T-1~T-5)의 실기기 확인 — ⬜ 미검증

정리 폴더에 아래 폴더들을 만들고 이미지를 넣은 뒤 **이미지 탭 → 정리 폴더 받아오기**.

1. **서랍이 낱개로 들이는가** — `기타/`에 새 이미지 3장. 사전 확인에
   <q>'기타' 서랍으로 낱개 편입: 3장</q>이 뜨고, 반영 뒤 **셋 다 링크 배지가 없는가**
   (종전에는 폴더끼리 묶여 링크가 생겼다 — 이번 변경의 본체다).
2. **예약판도 같은가** — `_기타/`로 같은 것을 반복. 결과가 1번과 같아야 한다.
3. **토큰 파일은 묶음만 풀리는가** — 이미 캐릭터에 배정되고 **수동 링크로 묶인** 이미지의
   내보낸 사본을 `기타/`에 넣는다. 반영 뒤 ① 링크가 풀렸는가 ② **캐릭터 배정은 그대로인가**
   (배정까지 풀리면 실패 — 그건 `_미배정/` 직속의 몫이다).
4. **자동 링크는 고지하는가** — 한 캐릭터에 이미지 2장 이상 + 설정의 `캐릭터 이미지 자동 링크`
   **켬** 상태에서 그중 하나를 `기타/`에 넣는다. 결과에
   <q>…캐릭터 자동 링크라 서랍에 넣어도 묶인 채로 남습니다…</q>가 뜨는가.
   **묶음이 실제로 그대로인가**(고지만 하고 푼 척하면 실패).
5. **캐릭터가 이긴다** — '기타'라는 **이름의 캐릭터를 만든 뒤** `기타/`에 새 이미지를 넣는다.
   그 캐릭터에 배정되고, 사전 확인에 <q>'기타' 캐릭터가 있어 … `_기타`를 쓰세요</q>가 뜨는가.
6. **링크 필터** — 이미지 탭 필터 줄 오른쪽의 `링크 전체 / 링크됨 / 링크 없음 / 캐릭터 자동`.
   각각 눌러 목록이 맞게 걸러지는가. **탭을 나갔다 와도 선택이 유지되는가**(영속 확인).
7. **흩어진 묶음 카드** — 3장 이상 묶인 그룹에서 **일부만** `기타/`에 넣어 묶음을 쪼갠다.
   결과에 <q>묶음이 나뉘면서 혼자 남은 이미지 N장</q>이 뜨고, 어시스턴트 탭에
   <q>묶음에서 떨어져 나온 이미지</q> 카드가 생기는가. 카드의 `이미지 탭에서 보기`를 누르면
   **'링크 없음' 필터가 걸린 채로** 열리는가. 그 이미지를 다시 묶으면 **카드가 사라지는가**.
   → **폴더를 통째로 서랍에 넣었을 때는 이 카드가 뜨면 안 된다**(의도한 잡동사니).
8. **AI 태그 — 미설정일 때** — AI 프로바이더를 지우거나 키를 빼고 `여행/` 같은 그 외 폴더로
   받아오기. 확인 다이얼로그에 **태그 제안 체크박스가 아예 없는가**(있으면 R-24 위반).
9. **AI 태그 — 설정 후** — 프로바이더 등록 후 `여행/`·`전투 장면/` 등 그 외 폴더 2~3개로
   받아오기. 체크박스와 <q>요청 N건</q> 고지가 뜨는가. 체크하고 반영하면 **결과 요약이 먼저**
   뜨고 그다음 검토 시트가 뜨는가. 시트에서 일부만 체크해 적용 → **체크한 것만** 붙었는가.
10. **적용 범위** — 9번의 폴더가 **기존 링크 그룹과 병합**되는 상황을 만든다(그 폴더의 이미지
    하나가 이미 다른 이미지와 묶여 있게). 태그가 **폴더에 넣은 이미지에만** 붙고 병합으로
    딸려 온 기존 이미지에는 안 붙는가.
11. **기조가 먹히는가** — 설정 → AI 연동 → `AI 이미지 태그 기조`에 예: "복장만 태그로
    뽑으세요"를 쓰고 9번을 반복. 제안 성격이 달라지는가. **화면을 나갔다 와도 문구가
    남아 있는가**(포커스를 둔 채 뒤로 가 보기 — 입력 유실 확인).
12. **어휘 토글** — 필드 편집 → 고급 → `AI 이미지 태그 어휘에 포함`을 켠 필드(예: 머리색)의
    값들이 제안 태그의 표기와 맞아 가는가. 끄면 영향이 없는가.

> **되돌리는 법:** 태그는 이미지 탭에서 지울 수 있고, 링크는 다시 묶을 수 있습니다.
> 어색하거나 원치 않는 결과가 나오면 알려 주세요 — 규칙을 바꿀 수 있습니다.

### 3-20. P3 전개 3단계(엑셀 문구, 1-k장)의 실기기 확인 — ⬜ 미검증

문구만 바뀐 변경이라 동작 회귀는 없어야 합니다. 확인할 것은 **문구가 실제로 도움이 되는가**뿐입니다.

1. **동명이인 행 오류 (이번 변경의 핵심)** — 같은 이름의 캐릭터를 2명 만들고, 엑셀로 내보낸 뒤
   `캐릭터 관계` 시트에 그 이름으로 관계 행을 하나 적습니다(`캐릭터1코드` 칸은 비운 채).
   다시 가져오면 이런 오류가 떠야 합니다:
   `관계 행 2: '○○' 이름의 캐릭터가 2명입니다 — '캐릭터1코드' 열에 코드를 적어 한 명을 지정하세요`
   → **여기서 부르는 열 이름이 실제로 그 시트에 있는 열과 같은지** 봐 주세요. 종전에는
   "코드(code) 열"이라고만 해서 어느 칸인지 찾아야 했습니다. 같은 확인을
   `관계 변화` 시트(`캐릭터1코드`/`캐릭터2코드`)와 `세력 소속` 시트(`캐릭터코드`)에서도 해 주세요.
2. **안내한 대로 고치면 통과하는가** — 1번에서 코드를 채워 다시 가져오면 오류 없이 들어가는가.
3. **세계관 이동 경고** — 캐릭터의 세계관을 엑셀에서 바꿔 가져오면
   "필드값 N개를 새 세계관 필드로 **다시 연결**"로 보입니다(종전 "재매핑"). 뜻이 통하는가.
4. **사용 안내 시트** — 내보낸 파일의 안내 시트에서 `[GRADE]` 줄이
   "등급 라벨과 수치를 **연결**"로, 코드 열 안내가 "코드를 **비워 두세요**"로 보이는가.
5. **월드패키지 오류 문구** — 앱이 아닌 곳에서 만든 ZIP을 가져와 보고
   "…앱에서 내보낸 파일인지 **확인하세요**"가 어색하지 않은가.
6. **설정 → 저장공간** — "내보내기의 임시 **파일**을 삭제합니다"로 보이는가(종전 "산출물").

> **판정을 부탁드리는 것 하나:** 이 문구들에 아직 남은 `매칭`이라는 말(예: "이름 기반 매칭")을
> 우리말로 바꿀지 정해 주세요. 이미 금지어인 `매핑`과 형제인데 등재가 빠져 있어 31곳에
> 남아 있습니다. ~~바꾸기로 하면 다음 단계(통계 화면)와 함께 처리하겠습니다.~~
> **→ 정정(전개 4단계 대조):** 31곳은 **전부 엑셀·검색 영역**이라 통계 화면과 묶이지 않습니다.
> 바꾸기로 하시면 엑셀 문구를 다시 여는 단계에서 한 번에 처리하겠습니다.

### 3-21. P3 전개 4단계(통계 화면, 1-l장)의 실기기 확인 — ⬜ 미검증

문구만 바뀐 변경이라 동작 회귀는 없어야 합니다. **다만 이번에는 화면 이름이 두 개 바뀌었으니
그 이름이 실제로 더 잘 맞는지**를 봐 주세요 — 어색하면 되돌리거나 다른 말로 바꾸면 됩니다.

1. **이름이 바뀐 자리 (되돌릴 수 있으니 편하게 봐 주세요)** — 통계 탭에서
   ① 종전 `패턴 인사이트` 카드 제목이 **`감지된 패턴`**으로 보이는가
   (그 아래 빈 문구가 원래 "감지된 패턴이 없습니다"라 이제 제목과 말이 맞습니다)
   ② 종전 `필드 인사이트` 카드·화면 제목이 **`필드 탐색`**으로 보이는가
   → **핵심 확인:** 바로 옆의 `커스텀 필드 분석` 카드와 **헷갈리지 않는가**.
   종전에는 '필드 인사이트'와 '커스텀 필드 분석'이 나란히 있었습니다.
2. **패턴 유형 설정** — 통계 화면 오른쪽 위 설정이 `패턴 유형 설정`으로 보이고, 유형을 몇 개
   끈 뒤 카드에 "…**패턴 유형** N개가 꺼져 있으니…"로 안내되는가.
   어시스턴트의 편향 카드가 비었을 때 뜨는 안내도 같은 이름을 부르는지 봐 주세요
   (종전에는 어시스턴트만 '인사이트 유형 설정'이라 불러 이름이 갈렸습니다).
3. **교차 분석 목적문 (이번 변경의 핵심)** — `필드 탐색` → 교차 분석을 여세요.
   창 맨 위에 **"고른 두 필드를 가로·세로에 놓고…"**가 보이고, 축 선택기 아래에
   **"셀 값을 캐릭터 수로 셀지 사건 수로 셀지 정합니다…"**가 보이는가.
   → 종전에는 이 설명이 **표를 만든 뒤에야** 나와서, 정작 축을 고를 때는 무엇이 정해지는지
   알 수 없었습니다. **고르기 전에 알겠는가**가 확인할 점입니다.
4. **축이 하나뿐일 때** — 캐릭터 필드만 2개 이상이고 사건 필드는 2개 미만인 세계관에서
   교차 분석을 열면, 축 선택기와 **그 목적문이 함께 사라지는가**(라벨만 남거나 설명만 남으면
   결함입니다).
5. **필터 목적문** — 같은 창의 필터 칸 위에 "고른 필드의 값이 일치하는 대상만…"이 보이는가.
6. **구조화 입력 칸 이름** — B-W-H 같은 구조화 입력 필드에서 **칸 이름을 비워 둔 채** 통계를
   보면 라벨이 `칸1`·`칸2`로 보이는가(종전 `파트1`·`파트2`).
7. **패턴 카드 제안 문구** — 편중·공백 등이 감지된 상태에서 카드의 💡 줄이
   "…**고려하세요**/**확인하세요**"로 보이는가(종전 "고려해보세요").

### 3-22. 엑셀 [800] '캐릭터 필드값' 시트의 왕복 — ⬜ 미검증

> **이관됨(2026-07-30).** `docs/excel_roundtrip_audit_2026-07.md` 2-2에 있던 항목인데,
> 그 문서는 감사 기록이고 **살아 있는 확인 목록은 이 3장이 소유한다**. 그 자리에만 있어
> 어느 목록에서도 보이지 않던 것을 옮겼다.

작품이 없는 캐릭터의 필드값이 엑셀 왕복에서 살아남는지를 봅니다.
**이 상태를 만드는 경로는 셋이며, 아무거나 하나면 됩니다:**

1. 캐릭터 일괄 편집 → '작품 없음'으로 이동(필드값이 보존된 채 미분류가 됩니다)
2. 작품이 삭제된 캐릭터를 휴지통에서 복원
3. 엑셀에서 캐릭터 행의 '작품'/'작품코드' 셀만 비우고 가져오기

그다음: 내보내기 → **[800] '캐릭터 필드값' 시트에 그 값이 있는지** 확인 →
앱 데이터를 지우고 그 파일로 복원 → 캐릭터를 원래 세계관의 작품에 재배정 →
**값이 되살아나는지** 확인해 주세요.

이어서 **구버전 백업 덮어쓰기**: '캐릭터 필드값' 시트가 **없는** 파일로 덮어쓰기를 하면
캐릭터 삭제를 건너뛰고 "복원할 수 없으므로 유지했습니다" 경고가 뜨는지 봐 주세요
(원 감사 문서 4-6 참조).

### 3-23. P-A(AI 제어·UI 밀도, A-0~A-4·N-1~N-2)의 실기기 확인 — ⬜ 미검증

> **이관됨(2026-07-30).** `docs/ai_control_and_ui_density_2026-07.md` 9장에만 있던 목록이다.
> CLAUDE.md 문서 지도가 **실기기 확인의 진입점을 이 문서로 지정**하는데 그 목록 밖에 있어,

9. 홈 도구의 `보충` 타일로 보충 화면에 도달하는가.
10. 목록 맨 아래 카드가 FAB에 가리지 않는가. 하단 탭 라벨이 두 줄로 접히지 않는가.

### 3-24. 값 라이브러리 정렬 크래시 수정의 실기기 확인 — ⬜ 미검증

**종전에는 크래시였습니다.** 필드 라이브러리 홈에서 정렬을 바꾼 뒤 값 목록으로 들어가면
(또는 그 반대) 앱이 죽었습니다. 두 화면이 같은 설정 키를 다른 타입으로 읽고 썼기 때문입니다.

1. **정방향** — 필드 라이브러리 홈 → 정렬 칩으로 '이름순' 선택 → 아무 필드나 눌러 값 목록 진입.
   **죽지 않아야 합니다.**
2. **역방향** — 값 목록에서 정렬을 바꾸고 뒤로 나가 홈의 정렬 칩을 눌러 봅니다. 역시 죽지 않아야 합니다.
3. **각자 기억하는가** — 두 화면의 정렬은 이제 **서로 독립**입니다. 홈은 '이름순',
   값 목록은 '사용 횟수순'처럼 다르게 두고 오가도 각자 유지되어야 합니다.
4. **기존 사용자 경로(중요)** — 이 수정 **전** 버전을 쓰던 기기라면 잘못된 값이 이미 저장돼
   있을 수 있습니다. 앱을 지우지 말고 덮어 설치한 뒤 위 1~2를 해 주세요.
   한 번은 정렬이 기본값으로 돌아갈 수 있는데 **정상**입니다(잘못된 값을 지우고 복구합니다).

### 3-25. P3 전개 5단계(말투 마무리 + 측정값 토글 라벨)의 실기기 확인 — ⬜ 미검증

**문구만 바뀌었고 기능은 그대로입니다.** 아래 다섯 자리에서 말투가 '~어요'에서
'~합니다'로 바뀌었는지, 그리고 마지막 항목의 라벨이 화면과 짝이 맞는지 봐 주세요.

1. **AI 설정 → OpenAI 안내** — 설정 > AI > 제공자에서 OpenAI를 고르면 뜨는 3번 항목이
   "(창을 닫으면 다시 볼 수 없습니다)"여야 합니다. 다른 제공자 안내와 말투가 같아야 합니다.
2. **자동 백업 고지** — 설정에서 자동 백업 안내 다이얼로그가 뜨는 경우,
   제목이 "자동 백업이 데이터 전용으로 바뀌었습니다"여야 합니다(본문은 종전과 같습니다).
3. **이미지 재압축 되돌리기(성공)** — 설정 > 이미지 관리에서 재압축을 실행하면
   '실행취소' 스낵바가 뜹니다. 누르면 **"원본을 복원했습니다"**여야 합니다.
4. **이미지 재압축 되돌리기(일부 실패)** — 일부만 복원되는 상황이 나오면
   **"일부 원본을 복원하지 못했습니다. 복원하지 못한 이미지는 재압축본으로 남습니다."**가
   떠야 합니다. **재시도를 권하지 않는 것이 의도입니다** — 되돌리기 정보는 한 번 쓰면
   비워지므로 다시 눌러도 결과가 달라지지 않습니다(그래서 남는 상태를 알립니다).
   이 경로는 일부러 만들기 어려우니 **나오면 확인**하는 정도로 충분합니다.
5. **측정값 분석 토글(중요)** — 캐릭터 필드 편집에서 신체 측정 필드의 '측정값 분석' 설정을
   열면 토글 목록이 나옵니다. 종전 **'정규화 비율'** 자리가 이제 **'보정 비율'**이어야 하고,
   그 토글을 켰을 때 **캐릭터 읽기 화면에 뜨는 줄 이름도 '보정 비율'**로 같아야 합니다
   (종전에는 설정과 화면의 이름이 달랐습니다).
   토글을 껐다 켰을 때 해당 줄이 사라지고 다시 나타나는 동작은 종전과 같아야 합니다.

> 나머지 토글 12개는 아직 설정과 화면의 이름이 다릅니다 — **B-61**로 등재했고
> 어느 이름을 살릴지는 판정이 필요합니다. 이 확인의 대상이 아닙니다.

### 3-26. P5(사건 필드 입력 마찰)의 실기기 확인 — ⬜ 미검증

**사건 필드를 만드는 길이 사건 편집 자리로 들어왔습니다.** 지금까지는 세계관 목록으로
되돌아가야 했고, 그래서 사건 필드가 0개였습니다.

1. **사건 편집에서 바로 만들기(핵심)** — 연표에서 사건을 추가하거나 편집하고,
   작품을 하나 고르십시오. 아래쪽에 **'사건 필드'** 머리글과
   "이 세계관에는 사건 필드가 없습니다…" 안내, **'사건 필드 추가'** 버튼이 보여야 합니다.
   버튼을 누르면 **필드 관리에서 쓰던 것과 같은 필드 편집 창**이 뜨고, 저장하면
   "사건 필드 '…'을(를) 추가했습니다" 알림과 함께 **그 자리에서 입력 칸이 생겨야** 합니다.
   **가장 중요한 것: 그때 이미 입력해 둔 사건 이름·연도·설명이 그대로 남아 있어야 합니다.**
2. **작품을 안 고른 상태** — 신규 사건에서 작품을 고르기 전에는 이 버튼이 **보이지 않아야**
   합니다(어느 세계관에 만들지 알 수 없기 때문입니다). 작품을 고르면 나타나야 합니다.
3. **캐릭터 쪽에서도 같은가** — 캐릭터 상세/편집의 사건 목록에서 사건을 편집할 때도
   같은 버튼이 보이고 같은 알림이 떠야 합니다(호스트가 셋입니다).
4. **필드 가져오기의 종류 구분** — 필드 관리에서 칩을 **'사건 필드'**로 바꾼 뒤
   메뉴의 '다른 세계관에서 필드 가져오기'를 누르면, 사건 필드가 있는 곳만 후보로 떠야 합니다.
   아직 아무 세계관에도 사건 필드가 없으면 **"가져올 사건 필드가 없습니다…"**가 떠야 합니다
   (종전에는 캐릭터 필드가 뜨고, 가져와도 목록에 아무것도 나타나지 않았습니다).
   사건 필드를 두 세계관에 만들어 두고 한쪽에서 가져오면 **목록에 실제로 나타나야** 합니다.
5. **프리셋에 사건 필드가 담기는가** — 사건 필드가 있는 세계관을 사용자 프리셋으로 저장한 뒤,
   그 프리셋으로 새 세계관을 만들면 **사건 필드도 함께 와야** 합니다(종전에는 조용히 빠졌습니다).
   프리셋 편집 화면에서는 사건 필드 행에 **`사건 필드 ·`** 접두가 붙어 구분돼야 합니다.
6. **구버전 프리셋이 멀쩡한가(중요)** — **이 변경 전에 저장해 둔 사용자 프리셋**을 열어
   필드 목록이 종전과 같이 보이고, 그것으로 세계관을 만들어도 캐릭터 필드가 정상인지
   봐 주세요(저장 형식이 바뀌었으므로 옛 프리셋의 호환이 확인 대상입니다 — 순수 테스트로는
   통과했습니다).

> **기본 사건 필드를 프리셋에 심는 것은 하지 않았습니다** — 모든 새 세계관이 받는 기본값이라
> 판정이 필요합니다(**B-62**). 그래서 지금도 **첫 사건 필드는 손으로 하나 만들어야** 합니다.
> 이 확인이 보려는 것은 "만들기가 쉬워졌는가"이며 "이미 있는가"가 아닙니다.

     불요(구조적으로 같은 작업이 되살릴 대상이 아님, 각 KDoc에 명시). 유일한 구멍 = **code 없는

   - **B-26**(되돌리기의 상태변화 보충 한계) — 위 표 참조.
   - 우선순위 1 산출물의 **실기기 확인 절차는 3-5장**에 있다.
7. 수정할 때마다 (1) 순수 JVM 테스트 (2) 차분 컴파일 (3) 리소스 점검,

   의심할 것** — 세 세션 모두에서 가장 심각한 결함이 정확히 거기서 나왔다.

   ### B-1 재공격이 잡은 것 중 되새길 만한 셋

   - **복원이 남의 엔티티에 붙었다.** code 충돌 시 재발급하는 처리(유니크 위반을 막으려고
     넣은 안전망)가, 같은 작업의 뒤 항목이 **옛 코드로 조회**한다는 사실과 맞물려 오배정을
     만들었다. R-1은 "코드가 대상을 정한다"인데, **그 코드가 방금 바뀔 수 있다는 것**을
     한 단계 더 생각해야 했다. 안전망은 자기 뒤에 오는 코드의 가정을 깬다.
   - **우선순위가 같은 둘 사이의 링크는 순서를 정할 수 없다.** 세력↔세력, 캐릭터↔캐릭터가
     그렇다. "한쪽만 담는다"는 규칙(R-8)은 우선순위가 **다를 때만** 성립하고, 같을 때는
     양쪽이 담고 먼저 오는 쪽이 조용히 양보해야 한다. 규칙을 세울 때 그 규칙이 성립하지
     않는 경계를 함께 적어 두지 않으면 절반의 확률로 유실이 난다.
   - **문구는 형제를 데리고 다닌다.** 보관 규칙을 바꾸면서 문구 4개를 갱신했는데
     `batch_delete_confirm_message` 하나가 남아 정반대를 안내했다. 규칙을 바꿀 때는
     그 규칙을 말하는 **모든** 문자열을 grep으로 훑을 것(`휴지통`·`30개`·`30일`).
   - **상한을 옮기면 그 상한에 기대던 코드를 전부 찾아야 한다.** `MAX_ITEMS=30`(행)을
     `MAX_OPERATIONS=30`(작업)으로 올린 순간, "행은 최대 30개"라는 전제 위에 서 있던
     코드가 전부 무너졌다 — 목록의 `SELECT *`(payload 수만 행), 휴지통 비우기의 O(n²),
     캐릭터마다 도는 라이브러리 수확, 그리고 세계관 payload 한 행이 CursorWindow 한도를
     넘어 **백업 자체를 읽을 수 없게** 되는 것까지. 상한은 코드 곳곳의 암묵적 계약이다.
   - **묶는 것은 의미를 부여하는 일이다.** 편집 직전 백업 12건을 operationId로 묶었더니
     그것이 곧 "삭제 묶음"으로 표시되고 원클릭 복제 버튼이 달렸다. 새 그룹핑 축을 도입할
     때는 그 축 위에 실리면 **안 되는** 것이 무엇인지 함께 정할 것.

   이번 재공격이 잡은 것 중 되새길 만한 셋:
   - **되찾기 로직이 남의 시트를 잡았다.** 예약 시트를 되찾으려고 만든 접미사 폴백이 첫 열만
     보고 판단해, 캐릭터 시트를 세력·이름 은행 시트로 읽었다. *복구를 위한 코드가 새로운
     오배정 경로를 만든 것* — 관대해질 때는 판별을 함께 좁혀야 한다.
   - **고지를 정교하게 만들다가 고지를 없앴다.** 복원 미리보기를 도입하면서 "이미 알렸으니
     반복하지 않는다"는 조건을 걸었는데, 그 조건이 *미리보기가 예측할 수 없는* 유실까지
     막아버렸다. 주석은 정반대를 약속하고 있었다 — 주석과 코드가 어긋나면 코드가 틀린 쪽이다.
   - **고지가 화면에 도달하지 않았다.** 저장 직후 `popBackStack`으로 뷰가 사라지는데 스낵바를
     그 뷰에 붙였다. 고지를 추가할 때는 *그 시점에 그 뷰가 살아 있는가*를 확인할 것.

   **가설은 반드시 실행으로 확인하라.** 이번 렌즈들은 임시 테스트를 추가해 실제로 돌려
   입증했고, 그중 값진 것은 영구 회귀 테스트로 편입했다(`SheetNameAssignmentTest`의
   헤더 판별·접미사 되찾기 4건). 정독만으로는 '첫 열이 같다'는 사실을 놓치기 쉽다.

   ⚠️ **반증 관문에 대해 (N1 세션의 실패를 반복하지 말 것).**
   N1 세션은 반증 전담 대부분이 세션 한도로 실패해 "확정 0건 / 기각 30건"이 나왔는데,
   **그것은 표가 0개라 기각으로 분류된 것일 뿐 반증된 것이 아니었다.**
   B-1 세션은 그 함정을 알고 집계 규칙을 뒤집었다 — **표가 돌아오지 않으면 생존으로 센다**
   (`votesReturned == 0 → survives`). 그리고 지적은 **전부 내가 코드를 직접 읽어 실재를
   확인한 뒤에만** 반영했다. 8건 모두 그렇게 확인해 고쳤다.

   다음 세션도 같은 규칙을 지킬 것: **판정이 돌아오지 않은 것을 '통과'로 세지 말 것.**
   그리고 반증이 늦더라도 지적을 코드로 직접 확인하는 것이 최종 관문이다 — 에이전트의
   판정은 보조이지 근거가 아니다.
