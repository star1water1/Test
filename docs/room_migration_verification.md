# Room 마이그레이션 검증 절차

> **상태: 현행 절차 — 스키마를 건드릴 때마다 쓴다.** (현재 DB 버전은 `AppDatabase.kt`의
> `version =`이 단일 소스다. 마이그레이션 개수의 세는 법:
> `grep -rhoE 'MIGRATION_[0-9]+_[0-9]+' app/src/main/java --include=*.kt | sort -u | wc -l`
> — 여기 값을 병기하던 관행은 두 판 연속 낡아 없앴다. v1→vN은 항상 N-1단계다.)
> 이 문서는 끝난 계획서가 아니라 **살아 있는 절차서**다.

DB 스키마 변경은 실패하면 **사용자 기기에서 앱이 기동하지 못한다**. 이 저장소는
`fallbackToDestructiveMigration()`을 쓰지 않으므로 데이터가 지워지지는 않지만,
마이그레이션이 잘못되면 Room이 시작 시 예외를 던져 앱을 열 수 없다.

로컬 하네스, Gradle 빌드·CI의 Room 계측 시험, 실기기 업그레이드의 3단계로 확인한다.
로컬에서 Android SDK나 에뮬레이터를 쓸 수 없어도 CI에서 2단계를 실행할 수 있다.
작업 범위와 완료 보고는 [AGENTS.md](../AGENTS.md), 현재 확인 대기는 [status.md](status.md)를 따른다.

## 1단계 — 자동 검증 (기기 불필요, 즉시 실행)

**하네스는 검증 대상 마이그레이션마다 파일을 따로 둔다** — 스크립트 하나에 계속 덧붙이지
않는다(옛 하네스가 여전히 대조군으로 돌아야 하기 때문이다). **전 마이그레이션을 소급
커버하는 것은 아니다** — 하네스 관행이 생긴 v43부터이며, 그 이전 구간은 초기 하네스의
대조군 검증만 받는다(종전의 "마이그레이션마다 하나씩 **있다**"는 45 대 5로 사실과 갈리는
현재형이었다 — 2026.08.01 정정, 적대 검토 2-3).

```
python3 tools/verify_room_migration.py       # 초기 하네스 (대조군 포함)
python3 tools/verify_room_migration_43.py    # v42 → v43 — 49건
python3 tools/verify_room_migration_44.py    # v43 → v44 (image_meta.adoptSource) — 25건
python3 tools/verify_room_migration_45.py    # v44 → v45 (작품 커스텀 필드, 확-3) — 23건
python3 tools/verify_room_migration_46.py    # v45 → v46 (grade_systems, U-1) — 23건
```

현행 전체 목록은 `ls tools/verify_room_migration*.py`가 든다(위 목록은 등재 시점 스냅샷).

새 마이그레이션을 추가하면 **`_<새버전>.py`를 새로 만든다.** 건수는 각 스크립트의 실행 결과를
믿을 것(문서의 숫자는 작성 시점 스냅샷이다).

의존성 없이 파이썬 내장 `sqlite3`만 사용한다. 하는 일:

1. **AppDatabase.kt에서 실제 마이그레이션 SQL 문장을 추출**해 실행한다.
   테스트가 SQL 사본을 갖고 있으면 코드와 어긋나므로, 항상 배포될 문장 그 자체를 검사한다.
2. 변경 직전 버전의 테이블을 실제 SQLite에 만들고 표본 행을 넣은 뒤 마이그레이션을 실행한다.
3. 실행 후 상태를 검사한다 — 기존 데이터 무변경, 전 행 백필, 값 고유성,
   기존 인덱스·외래키 유지, 유니크 제약 실동작.
4. **Room 스키마 검증 통과 조건**을 대조한다. Room은 시작 시 실제 스키마와 엔티티에서
   유도한 기대 스키마를 비교해 하나라도 어긋나면 예외를 던진다. 특히 자주 어긋나는 지점:
   - 컬럼 타입 affinity (TEXT/INTEGER/REAL/BLOB)
   - notNull 여부 — 엔티티가 `String?`이면 `ADD COLUMN ... TEXT` (NOT NULL 금지)
   - DEFAULT 절 — 엔티티에 `@ColumnInfo(defaultValue)`가 없으면 SQL에도 DEFAULT를 두면 안 된다
   - 인덱스 이름 — Room 규약은 `index_<table>_<col1>_<col2>`
5. 빈 테이블·재실행(컬럼이 이미 있는 기기) 안전성을 검사한다.
6. **대조군**: 이미 배포되어 정상 동작 중인 과거 마이그레이션을 같은 하네스로 돌려
   하네스 자체가 올바른지 교차 검증한다.

## 2단계 — 빌드·스키마와 실제 Room 검증 (로컬 또는 CI)

```
./gradlew :app:assembleDebug
```

위 명령은 Android SDK와 Gradle 의존성을 사용할 수 있는 환경에서 실행한다.
Room 애노테이션 프로세서가 엔티티에서 기대 스키마를 생성한다. 산출 위치는
`app/schemas/com.novelcharacter.app.data.database.AppDatabase/<버전>.json`이며,
이미 커밋된 스키마도 이 디렉터리에 있다. 새 JSON은 빌드 산출물을 그대로 사용하고
`identityHash` 등을 손으로 작성하지 않는다. **빌드 성공만으로 마이그레이션 등록과
기존 DB 업그레이드의 정확성이 증명되지는 않는다.**

- `.github/workflows/build-apk.yml`은 정적·스키마 하네스, 단위 시험, APK 빌드를 실행하고
  `room-schemas` 아티팩트를 올린다. 같은 저장소의 브랜치에서는 변경된 스키마를 자동 커밋하며,
  포크 PR에서는 아티팩트의 JSON을 PR 브랜치에 반영해야 한다.
- `.github/workflows/migration-test.yml`은 DB·스키마 등 지정 경로가 바뀐 PR에서
  `AppDatabaseMigrationTest`를 포함한 계측 시험을 에뮬레이터의 실제 Room으로 실행한다.
  자동 실행 대상이 아니면 해당 작업 브랜치에서 `workflow_dispatch`로 실행한다.
- 스키마 자동 커밋은 `GITHUB_TOKEN`을 사용하므로 그 커밋이 후속 워크플로를 자동으로 깨우지 않는다.
  새 JSON이 반영된 PR head에서 마이그레이션 검증이 필요한데 실행되지 않았다면 위 수동 실행을 사용한다.
  검토한 head와 실제 검사 대상 커밋·결과를 함께 확인하고, 스키마 부재로 건너뛴 시험을 통과로 보고하지 않는다.

CI가 확인하는 것은 시험에 포함된 마이그레이션 경로와 데이터다. 사용자의 실제 DB·기기 확인은 3단계에 남긴다.

## 3단계 — 실기기 업그레이드 (배포 전 필수 1회)

1·2단계의 자동 검증과 별도로, 실제 기기의 기존 사용자 데이터로 업그레이드 결과를 확인한다.

1. **변경 전** 커밋으로 빌드해 설치하고, 데이터를 몇 건 만든다(관계·사건·세력 소속 포함).
2. 앱을 **지우지 말고** 변경 후 빌드를 덮어 설치한다.
3. 앱을 켠다. 정상 기동하면 마이그레이션과 Room 스키마 검증을 모두 통과한 것이다.
4. 기존 데이터가 그대로인지, 새 열이 채워졌는지 확인한다
   (예: 엑셀로 내보내 새 코드 열에 값이 있는지).

실패 시 로그에 `Migration didn't properly handle` 또는 `Migration from X to Y` 예외가 남는다.

## 체크리스트

- [ ] 엔티티 필드가 nullable이면 SQL도 NOT NULL 없이 추가했는가
- [ ] `@ColumnInfo(defaultValue)`를 쓰지 않았다면 SQL에도 DEFAULT가 없는가
- [ ] 인덱스 이름이 Room 규약과 일치하는가
- [ ] `@Database(version = N)`을 올렸는가
- [ ] `addMigrations(...)`에 새 마이그레이션을 등록했는가
- [ ] 백필이 유니크 인덱스 **생성 전에** 끝나는가
- [ ] 컬럼이 이미 존재하는 기기에서 재실행해도 안전한가
- [ ] 새 마이그레이션용 `tools/verify_room_migration_<버전>.py`를 **만들었고** 통과하는가
- [ ] 기존 하네스(대조군)도 여전히 통과하는가
- [ ] 빌드가 생성한 스키마 JSON을 PR에 반영했는가
- [ ] 검토한 PR head에서 관련 빌드·Room 계측 시험 결과를 확인했는가
- [ ] 실기기 업그레이드 1회 확인
