### 앞 판이 낸 것 (2026.08.20) — **사용자 요청: AI 메시지 양식 편집 + 엑셀 설정 안내**

**사용자가 직접 연 기능 판이다** (백로그 밖). 원문 둘:
*"ai api에 보내지는 메세지 양식도 모두 사용자가 편집할 수 있게 하기(인앱, 엑셀 모두)."* ·
*"엑셀에서 지금 설정을 편집할 수는 있는 거로 알고 있는데 각각의 칸이 뭘 의미하고 어떤 입력을
받는지를 알 방법이 없거든? 사용자 친화적인 가이드가 있으면 좋겠어."*

| 무엇 | 요청 원문의 몫 |
|---|---|
| **메시지 양식 열넷을 열었다** — 기능 7종 × (지시문 · 재료). 종전에는 전부 서제스터 안의 하드코딩 문자열이었다 | *"메세지 양식도 모두 사용자가 편집할 수 있게"* |
| **인앱 편집 화면** — 설정 → AI → 'AI 메시지 양식'. 자리표를 칩으로 넣고, 검증 실패는 창을 안 닫고 그 칸에 붙는다 | *"(인앱…)"* |
| **엑셀 편집** — '앱 설정' 시트에 행 열넷. 빈 칸은 기본 양식으로 되돌리기다 | *"(…엑셀 모두)"* |
| **'앱 설정' 시트에 `설명`·`입력 가능한 값` 두 칸** — 행마다 그 설정이 무엇이고 어떤 값을 받는지. **문구는 상수에서 생성한다**(R-14) | *"각각의 칸이 뭘 의미하고 어떤 입력을 받는지"* |
| **'사용 안내' 시트에 두 절** — `'앱 설정' 시트` · `AI 메시지 양식`. 열일곱 시트를 다루면서 이 시트만 한 줄도 없었다 | *"사용자 친화적인 가이드"* |

**핵심 결정 넷:**
- **잠근 것은 자리표로 잠갔다.** 응답 형식과 `[추천할 필드]` 절은 배열 이름 하나만 달라져도
  읽는 쪽이 **0건**을 보고, 사용자는 *"형식 오류"*와 함께 돈 낸 요청을 잃는다. 그래서
  `{{응답형식}}`·`{{추천할필드}}`를 **필수 자리표**로 뒀다 — **자리는 사용자가, 내용은 앱이.**
- **막는다.** 수식 편집은 *"그대로 저장"*을 여는데 여기는 거절한다 — 자리표 어휘는 앱이 정하는
  닫힌 목록이라 모르는 이름은 오타 말고 될 것이 없고, 오타는 글자 그대로 실려 나간다.
  다만 **창을 닫지 않고 그 칸에 사유를 붙인다**(R-27).
- **펼친 값은 다시 훑지 않는다.** 훑으면 캐릭터 메모에 적어 둔 `{{…}}`가 프롬프트 구조를 바꾼다.
- **`{{…}}`를 고른 것은 홑중괄호와 `@`를 피한 결과다.** 양식 본문에 JSON 보기가 그대로 있고,
  엑셀은 칸 첫 글자 `@`를 함수로 읽는다(R-40에 등재).

**함께 고친 것 — 하드코딩된 규칙 번호 `16.`:** 근거 강도 지시가 `16.`으로 시작하고
*"규칙 5대로"*를 가리켰다. 규칙 본문이 사용자 손에 들어간 이상 **그 번호는 반드시 어긋난다**
(열둘로 줄이면 1~12 다음에 16, 스물로 늘리면 16이 두 번). 번호를 버리고 이름표 블록으로 바꿨고,
**그 덕에 사건 축의 사본이 사라져 두 축이 한 벌을 쓴다.**

**프로브 범위에 `ai/`를 들였다.** 이 판이 `excel/` → `ai/` 간선을 만들자 **`AppSettingsKeys`
하나에서만 신규 오류 61건**이 떴는데 전부 *범위 밖*의 그림자였다 — 그런 수는 다음 판이 기준선을
견줄 때 진짜 결함을 덮는다. `share/`·`data/`와 같은 꼴로 폴더째 들이고 셋만 이름으로 뺐다
(`AiService`·`AiKeyStore`·`AiModelSuggestions` — OkHttp·암호화 저장소).

**받쳐주는 확장성 판정(체크리스트 6 — 7장 4단계):** ① 새 상한 하나(양식당 8,000자) —
**버려지는 것은 없다**(넘치면 자르지 않고 거절하며 기존 양식이 남는다) · ② 비용이 규모 축
(캐릭터·필드값·관계 수)에 붙지 않는다. 요청당 문자열 하나이고 설정이 열넷 는다 ·
③ `StatsSnapshot`을 안 키운다 · ④ 엑셀은 **열 2개 + 행 14개**. 새 시트는 만들지 않았다
('앱 설정'은 60행 규모라 스트리밍 적재 단위를 좌우하지 않는다).

**실기기 몫은 `3-147`(8항)로 등재** — 자리표 펼치기·검증·왕복은 시험이 잠갔고, 편집 창이
회전에서 사는가·엑셀이 여러 줄 셀을 어떻게 그리는가·셀 줄바꿈이 무슨 글자로 오는가는 기기만 안다.

## 1. 판의 정의 — **사용자가 앱에서 볼 수 있는 변화가 없으면 판이 아니다**

**2026.08.19 사용자 판정.** 종전에는 도구·검사·문서만 바꾸는 세션도 한 판으로 셌고,
그것이 실측으로 **최근 20판 중 6판(30%)**이었다. 같은 기간 앱 코드 4,220줄에
도구·문서 6,683줄이 붙었다 — **메타작업이 산출물의 1.6배**였다.

- **한 판은 사용자가 앱에서 볼 수 있는 변화를 하나 이상 낸다.**
- **도구·검사·문서 작업은 독립 판으로 열지 않는다.** 기능 판에 딸려 간다.
- **예외는 사용자가 지시했을 때뿐이다**(전례: 이 문서를 만든 판, 콜드 검토 지시).
- **검사·도구는 동결에 가깝게 다룬다.** 새 검사는 *같은 부류의 앱 결함이 실제로 두 번 난 자리*에만.
  현재 51종·14,937줄이고, 그것들이 잡은 것의 대부분은 **다른 검사와 도구의 결함**이었다.

### 완료의 정의

- **병합은 CI 초록으로 완료된다.** 실기기 확인은 병합을 막지 않는다.
- **실기기 확인은 별도 큐**(`device_walkthrough.md`)에 쌓고 **회차 단위로 소화**한다.
  종전 규칙(*"화면 변경은 실기기 확인 전까지 완료로 보고하지 않는다"*)은
  갚을 수 없는 부채를 만들어 **세션이 화면을 피하게 했다** — 그래서 바꿨다.

## 4. 재현 기준선 — 손대기 전에 이 숫자부터 맞춘다

```bash

JARS_DIR=<스크래치패드> tools/run_jvm_tests.sh      # 순수 JVM 시험
JARS_DIR=<스크래치패드> tools/probe_compile.sh /tmp/probe.txt

for p in tools/verify_room_migration*.py tools/verify_reset_coverage.py; do python3 "$p"; done
```

**현행 값(2026.08.20 검토 판):** 시험 **3527** · 프로브 **540** · 커스텀 뷰 프로브 **0** · 검사 **51종**

- ℹ️ **프로브 540은 줄어든 값이고, 스텁이 좋아진 결과다.** 검토 판이 프로브 스텁 셋을 좁게
  실타입화했다(`Activity`·`ContentResolver`·`DocumentsContract.deleteDocument` —
  LruCache·B-190 전례). −33은 종전 `Any?` 수신이 숨기던 미해석의 해소이지 결함 감소가
  아니다. **손대기 전에 master에서 한 번 떠 보고 견줄 것**은 그대로다.

- ℹ️ `triage_unresolved.sh`는 master에서 종료코드 1이다 — 프로브가 뺀 타입을 그대로 이름으로

  2026.08.20부터 `AiKeyStore`), **결함이 아니라 범위의 그림자다.**
  **손대기 전에 master에서 한 번 떠 보고 견줄 것** — 안 그러면 남의 빨간불을 자기 것으로 읽는다.

- ⚠️ **`run_jvm_tests.sh`의 종료 코드는 시험 실패를 말하지 않는다** — 언제나 0이다.

- ⚠️ **프로브 기준선을 뜨기 전에 `git fetch origin master`를 먼저 한다.**
  낡은 `origin/master`로 뜨면 프로브가 거짓말을 한다(양방향으로).

## 왜 이 문서가 생겼나 — 실측

사용자 질문(2026.08.19): *"개발이 끝이 안 나는데 원인이 뭐고 어떻게 해결할 수 있을까?"*

| 재는 것 | 실측 |
|---|---|
| 백로그 **250건** 중 사용자가 연 것 | **1건** (나머지는 콜드 검토 20 · 점검 18 · 감사 12 · 앞 판/착수 대조…) |
| 최근 20판의 산출 | 앱 코드 **4,220줄** vs 문서 4,235 + 도구 2,448 = **6,683줄** |
| 앱 코드를 한 줄도 안 바꾼 판 | **20판 중 6판** |
| `remaining_work` 크기 | 5일 만에 16,342 → **21,691줄** |
| 앱에서 화면(`ui/`) 비중 vs 그걸 보는 시험 | 코드의 **48%** / 시험의 **8%** |
| **실기기 확인 통과** | **7건 · 마지막 2026-08-01 · 그 뒤 52판** |

**뿌리는 하나다.** 실기기 확인이 멈추자 화면 부채가 쌓였고, 세션은 그 부채를 갚을 수 없으니
**부채를 안 만드는 일**(도구·검사·문서)로 흘렀다. 화면을 자동으로 못 보니 검사를 만들었고,
검사는 자기가 볼 수 있는 것 — **자신과 다른 도구** — 을 검사하기 시작했다.
그 활동이 백로그를 자가발전시켰고(249/250), 문서를 키웠고, 커진 문서가
**부채를 은폐했다**(인수인계 판은 줄곧 "열다섯"이라 적었는데 실제로는 124건이었다).

**그래서 고친 것은 둘이다:** 판의 정의(1장)와 문서 크기(이 문서).
**고치지 않기로 한 것도 적어 둔다** — 콜드 검토·자기 등재·검사 신설은 사용자가 이번에
자르지 않았다. 다시 자가발전이 보이면 그때 다시 잰다.
