- **실기기 확인은 별도 큐**(`device_walkthrough.md`)에 쌓고 **회차 단위로 소화**한다.
  종전 규칙(*"화면 변경은 실기기 확인 전까지 완료로 보고하지 않는다"*)은
  갚을 수 없는 부채를 만들어 **세션이 화면을 피하게 했다** — 그래서 바꿨다.

## 4. 재현 기준선 — 손대기 전에 이 숫자부터 맞춘다

```bash
JARS_DIR=<스크래치패드> tools/setup_jvm_env.sh      # 세션마다 1회
JARS_DIR=<스크래치패드> tools/run_jvm_tests.sh      # 순수 JVM 시험
JARS_DIR=<스크래치패드> tools/probe_compile.sh /tmp/probe.txt
JARS_DIR=<스크래치패드> tools/probe_view_compile.sh /tmp/view.txt
for f in tools/check_*.sh; do "$f" || echo "FAIL $f"; done
for p in tools/verify_room_migration*.py tools/verify_reset_coverage.py; do python3 "$p"; done
```

**현행 값은 여기 적지 않는다 — 0장의 「기준선(판 끝 실측)」 한 줄이 정본이다.**
같은 수가 두 자리에 살면 한쪽이 반드시 낡는다(콜드 검토 2026.08.21: 이 자리가 실제로
`3533`·`541`을 든 채 0장과 갈려 있었고, 5장 착수 절차가 *"기준선을 재현한다(4장)"*이라
지시하므로 다음 세션이 자기 변경이 수십 건을 만들었다고 오독할 자리였다).
**손대기 전에 위 명령을 한 번 돌려 그 출력을 기준선으로 삼는다.**

- ℹ️ **프로브 541은 줄었다가 하나 는 값이고, 둘 다 스텁의 그림자다.** 검토 판이 프로브 스텁
  셋을 좁게 실타입화해(`Activity`·`ContentResolver`·`DocumentsContract.deleteDocument` —
  LruCache·B-190 전례) 종전 `Any?` 수신이 숨기던 미해석 33건이 걷혔고, 콜드 검토 수리가
  런처 콜백(스텁에서 `Any`)을 실타입 인자로 쓰는 자리 하나를 더해 같은 부류의 그림자가
  한 줄 늘었다(`ExcelTransferController` — 같은 줄이 기준선에 이미 있다).
  **손대기 전에 master에서 한 번 떠 보고 견줄 것**은 그대로다.

- ℹ️ `triage_unresolved.sh`는 master에서 종료코드 1이다 — 프로브가 뺀 타입을 그대로 이름으로
  보고하기 때문이고(`ExcelImporter`·`AppSettingsBindings`·`CappedScrollView`·`TaskProgressDialog`,
  2026.08.20부터 `AiKeyStore`), **결함이 아니라 범위의 그림자다.**
  **손대기 전에 master에서 한 번 떠 보고 견줄 것** — 안 그러면 남의 빨간불을 자기 것으로 읽는다.

- ⚠️ **`run_jvm_tests.sh`의 종료 코드는 시험 실패를 말하지 않는다** — 언제나 0이다.
  산출에서 `OK (` / `FAILURES!!!`를 볼 것.
- ⚠️ **프로브 기준선을 뜨기 전에 `git fetch origin master`를 먼저 한다.**
  낡은 `origin/master`로 뜨면 프로브가 거짓말을 한다(양방향으로).
- ⚠️ **문서의 숫자보다 실제 실행 결과를 믿을 것.**

## 왜 이 문서가 생겼나 — 실측

사용자 질문(2026.08.19): *"개발이 끝이 안 나는데 원인이 뭐고 어떻게 해결할 수 있을까?"*

| 재는 것 | 실측 |
|---|---|
| 백로그 **250건** 중 사용자가 연 것 | **1건** (나머지는 콜드 검토 20 · 점검 18 · 감사 12 · 앞 판/착수 대조…) |
| 최근 20판의 산출 | 앱 코드 **4,220줄** vs 문서 4,235 + 도구 2,448 = **6,683줄** |
| 앱 코드를 한 줄도 안 바꾼 판 | **20판 중 6판** |
| `remaining_work` 크기 | 5일 만에 16,342 → **21,691줄** |
| 앱에서 화면(`ui/`) 비중 vs 그걸 보는 시험 | 코드의 **48%** / 시험의 **8%** |
| **실기기 확인 통과** | **7건 · 마지막 2026-08-01 · 그 뒤 52판** |

**뿌리는 하나다.** 실기기 확인이 멈추자 화면 부채가 쌓였고, 세션은 그 부채를 갚을 수 없으니
**부채를 안 만드는 일**(도구·검사·문서)로 흘렀다. 화면을 자동으로 못 보니 검사를 만들었고,
검사는 자기가 볼 수 있는 것 — **자신과 다른 도구** — 을 검사하기 시작했다.
그 활동이 백로그를 자가발전시켰고(249/250), 문서를 키웠고, 커진 문서가
**부채를 은폐했다**(인수인계 판은 줄곧 "열다섯"이라 적었는데 실제로는 124건이었다).

**그래서 고친 것은 둘이다:** 판의 정의(1장)와 문서 크기(이 문서).
**고치지 않기로 한 것도 적어 둔다** — 콜드 검토·자기 등재·검사 신설은 사용자가 이번에
자르지 않았다. 다시 자가발전이 보이면 그때 다시 잰다.
