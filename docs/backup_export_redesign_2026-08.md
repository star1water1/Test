# 백업·내보내기 동선 재편 — "백업은 버튼 하나" (2026-08)

> **상태: 설계 확정(2026.08.01) — 구현 대기.** 구현 순서는 사용자 확정: **체형 실루엣
> 구현(`body_visual_redesign` 10장) 다음 슬라이스.**
>
> **발단:** 실기기 확인 절차(`remaining_work` 3장 우선순위)의 첫 단계 "백업"에서 사용자가
> 실제로 막혔다 — "자동백업을 내가 격발시킬 방법이 없어보이는데? 그리고 그냥 백업만
> 내보내면 이미지는 같이 안 나가는데" → "뭐가 이렇게 복잡해? 이래서 앱이 제대로
> 쓰이겠어?" 재편 방향 3안(원탭 전체 백업 · 지금 백업 · 용도 분리)은 같은 대화에서
> 사용자가 승인했다("그렇게 해. 그리고 설계에 문제 없는지 제대로 확인하고 진행해").
>
> 이 문서는 대화 없이 읽혀야 한다 — 실측·진단·결정·검토를 전부 본문에 담았다.
> 흡수하는 백로그: **B-86**(해소), **B-51의 엑셀 몫**(부분 해소), **B-73**(곁다리 W-1).

## 1. 현행 실측 (2026.08.01, 파일:심볼 기준 — 코드로 확인한 사실만)

앱의 "데이터가 밖으로 나가는 길"은 다섯 갈래다:

| 경로 | 격발 | 산출물 | 이미지 | 진행도 표시 |
|------|------|--------|--------|------------|
| **자동 백업** | 주기 전용(1일, `PeriodicWorkRequestBuilder` — `NovelCharacterApp.scheduleAutoBackup`). **수동 격발 경로 없음** | 내부 `.enc`(암호화, 기본 기기 전용) | 설정 토글(`BackupSettingsStore.includeImages`) — **기본 제외**(저장 공간 결정, `archive/storage_optimization_design`) | 백그라운드(상태 카드·이력·실패 알림) |
| **엑셀 내보내기** | 설정·홈·세계관·작품 4곳 → `ExcelTransferController.showExportDialog` | `.xlsx` 또는 이미지 포함 `.zip` | 항목 선택 18개 중 **마지막** 체크박스 "이미지 (파일 크기 증가)" — **기본 꺼짐**(`ExportOptions.images = false`) | **조회형 스피너**(`createProgressDialog` — R-26 위반, B-51의 엑셀 몫) |
| **백업 내보내기** | 설정(`backup_export_to_external`) | 기존 `.enc`의 반출(이식 가능/기기 전용 선택) | 그 `.enc`가 담은 만큼(= 대개 없음) | 저장 스피너 |
| **월드패키지** | 설정(`exportWorldPackage`) | `.ncworld` | **토글 미배선**(B-73 — 문자열 4키 죽은 정의) | — |
| **이미지 폴더 내보내기** | 설정(`organizeFolderExportRow`) | 폴더 사본 | 이미지 자체가 대상 | R-26 규격(폴더 왕복이 신설) |

**재사용 가능한 인프라(이 재편의 비용이 작은 이유):**

- `AutoBackupWorker.doWork`가 이미 **완전한 백업 파이프라인**이다 — `ExcelExporter.populateWorkbook`(내보내기와 단일 소스, 드리프트 방지 주석 명시) → 이미지 zip 래핑(`ImageZipHelper`) → 암호화 → 회전 → 상태 기록 → 실패 시 재시도 3회 + 시스템 알림. **'지금 백업'은 이 워커를 `OneTimeWorkRequest`로 부르는 배선뿐이다.**
- `ExportOptions.ALL_WITH_IMAGES`가 **이미 정의돼 있는데 어떤 UI도 쓰지 않는다.** 원탭 전체 백업의 옵션 값이 이것 그대로다.
- 이미지 포함 결과 고지는 배선 완료 — 전부 담김/일부 누락(`export_images_incomplete`)/한 장도 못 담음/이미지 0장(`export_images_none`) 네 갈래 + 사유 상세. 확장자도 실제 산출물에서 파생(이미지 0장이면 `.xlsx`).
- '전부 선택' 버튼은 이미지까지 켠다(`ExportOptionsDialog` — 인덱스 전체 `turnOn`). **기본 경로가 문제다**: 17개가 미리 켜져 있어 사용자는 "이미 다 선택됐네"로 읽고 확인을 누른다 — 마지막 하나(이미지)가 꺼져 있다는 사실이 스크롤 밖이다.

## 2. 진단 — 왜 "백업했다"가 반쪽이 되는가

1. **격발 부재(B-86).** 파괴적 작업 직전에 백업을 만들 수단이 "다음 주기(최대 하루)를
   기다린다"뿐. R-4(파괴적 동작 전 안전망)의 실무 공백.
2. **완전성이 마지막 체크박스다.** 백업의 생명은 완전성인데, 이미지가 18항목 중 맨 끝·
   기본 꺼짐·"(파일 크기 증가)" 비용 프레이밍으로 앉아 있다. 모르면 반쪽 백업이 되고,
   그 사실은 결과 고지에야 나온다(고지는 모범적이나 **선택 시점의 방어가 없다**).
3. **계통 이원화가 무고지다.** 자동(.enc, 데이터 전용)과 수동(엑셀)의 능력 차이를
   사용자가 조립해서 알아야 한다. `backup_image_notice`가 한 번 뜨지만 1회성이다.
4. **작업형 로딩이 스피너다.** 내보내기는 항목 순회형 대량 작업인데 결정형 진행도가
   없다(R-26 위반 — B-51이 "2순위: 엑셀 내보내기(진행도 전무)"로 이미 지목).
5. **한 다이얼로그가 두 직업을 겸한다.** "전부 안전하게 보관"(백업)과 "표로 뽑아 작업"
   (데이터 추출)은 원하는 기본값이 정반대인데 같은 18체크박스를 쓴다. 원칙 04의 이중
   경로(러프/정밀)가 이 영역에만 없다.

## 3. 확정 결정 (D1~D6 — 사용자 승인 3안의 구체화)

- **D1. '전체 백업' 원탭 버튼.** 옵션 = `ExportOptions.ALL_WITH_IMAGES` 고정, 체크박스
  없음. 흐름: 버튼 → (공유/파일 저장 선택 — 현행 모드 선택 유지) → **결정형 진행도**
  → 완료 고지("이미지 N장 포함 — 완전한 백업입니다" / 누락 시 기존 4갈래 고지).
  위치는 **둘**: 설정 '백업/복원' 섹션 **최상단** + 홈 엑셀 카드 다이얼로그의 **첫 항목**
  (내보내기·가져오기 위). 목적문(R-25): "모든 데이터와 이미지를 한 파일(zip)로
  내보냅니다. 기기 이전·복구용입니다."
- **D2. '지금 백업' 버튼.** 설정 '자동 백업 상태' 카드에 추가 — `OneTimeWorkRequest`로
  `AutoBackupWorker` 재사용(파이프라인·회전·상태 기록 전부 공짜). 실행 중 재탭은
  비활성+사유, 완료·실패는 상태 카드 갱신 + 토스트 1줄. **산출물 성격은 자동 백업과
  동일**(기본 데이터 전용 .enc)임을 버튼 아래 한 줄로 고지 — D1과 헷갈리지 않게
  ("지금 백업 = 내부 보관용 스냅샷, 전체 백업 = 반출용 완전 사본").
- **D3. 용도 분리 리프레이밍.** 내보내기 진입(4곳 공통 `showExportDialog`)을 2단으로:
  **[전체 백업(이미지 포함)] / [골라서 내보내기(고급)]**. '골라서'는 현행 18항목
  다이얼로그 그대로(이미지 기본 꺼짐·크기 라벨 **유지** — 데이터 작업 용도에는 그
  기본값이 옳다). 기능 삭제 0(원칙 03) — 기본 경로만 직업에 맞게 갈린다.
- **D4. 자동 백업 기본값은 데이터 전용 유지.** 저장 공간 결정(이미지 ×N벌 상주 문제)을
  뒤집지 않는다 — 완전 백업의 직업은 D1이 가져간다. 이미지 포함 토글·보관 개수는 현행
  그대로. 상태 카드의 "이미지 제외" 상시 표기(현행 `backup_options_value`)도 그대로.
- **D5. 진행도 규격화.** D1·D2·'골라서' 전부 R-26 작업형 규격(`TaskProgressDialog` —
  시트/이미지 단위 진행, 안전한 지점 취소). **B-51의 엑셀 내보내기 몫이 여기서 해소**된다
  (가져오기 몫·이미지 대량 작업 몫은 B-51에 남는다).
- **D6. 대용량 사전 고지(변수 제어).** D1 확인 단계에서 이미지 총 크기 견적을 한 줄로
  ("이미지 약 1.2GB 포함 — 시간이 걸릴 수 있습니다"). 계산은 `ImageMeta` 파일 크기 합산
  1쿼리. 견적 실패 시 생략(견적은 편의이지 게이트가 아니다 — 조용히 막지 않는다).

**곁다리 W-1 (B-73):** 월드패키지 '이미지 포함' 토글 배선 — 죽은 문자열 4키가 이미
정의돼 있고 수신측 고지도 배선돼 있어, 내보내기 다이얼로그에 토글 하나 다는 일이다.
같은 슬라이스에 붙이는 것을 권고(성격 동일: "반출물의 완전성 선택이 보이는가").
기각이면 B-73 원문대로 4키를 지운다.

**하지 않는 것(범위 밖 — 오해 방지):** ① 두 계통(.enc/엑셀)의 통합 — 암호화·기기 전용/
이식 구분은 실가치가 있고 별개 판정이다 ② 자동 백업 주기·보관 정책 변경(B-74가 별도로
든다) ③ 가져오기 쪽 재편(수용·교정 규약은 현행 유지).

## 4. 화면 구성

**설정 → 백업/복원 섹션 (재배열):**

```
[전체 백업]  ← 신설, 채움 강조는 아니고 목록 행(규칙 2 — 화면당 채움 1개 원칙 준수)
  "모든 데이터와 이미지를 한 파일(zip)로 내보냅니다. 기기 이전·복구용입니다."
[골라서 내보내기]  ← 현행 '내보내기' 행 개명 — 항목 선택 18개(고급)
[가져오기]
─────
자동 백업 상태 카드
  마지막 성공 · 파일 N개 (총 M MB) · 이미지 제외      [지금 백업]  ← 신설
  "지금 백업 = 내부 보관용 스냅샷입니다. 반출용 완전 사본은 '전체 백업'을 쓰세요."
[자동 백업 옵션] [백업 복원] [백업 내보내기]  ← 현행 유지
```

**홈 → 도구 → 엑셀 카드 다이얼로그:** `[전체 백업] / [골라서 내보내기] / [가져오기]`
3항목(현행 2항목에서 확장 — 세계관·작품 목록의 진입도 컨트롤러 공용이라 자동 동일).

**문구(초안 — 구현 시 `check_text_style.sh` 통과 + R-25):** 위 목적문 2건과 완료 고지
"이미지 N장 포함 — 완전한 백업입니다"(누락 갈래는 기존 `export_images_*` 재사용).
"백업"·"내보내기" 용어는 현행 strings 관행 유지, 새 개념어 도입 없음.

## 5. 새 기능 체크리스트 판정 (CLAUDE.md 7항목)

① **확장성** — 옵션 축소 없음: '골라서'가 현행 전체 표면 유지, D1은 기본값 프리셋일 뿐.
② **실질성** — "백업했는데 반쪽"을 구조적으로 차단 — 실사용자가 실제로 걸린 자리.
③ **완결성** — 신규 파이프라인 0(전부 기존 단일 소스 재사용: `populateWorkbook`·
`ALL_WITH_IMAGES`·`ImageZipHelper`·고지 4갈래·회전·상태 기록). 방편식 분기 없음.
④ **연결성** — 4개 진입 프래그먼트가 컨트롤러 공용이라 한 곳 수정으로 전파. B-86 해소·
B-51 부분 해소·B-73 곁다리 흡수. ⑤ **조작성** — 백업이 3탭(진입→모드→완료)으로,
지금 백업이 1탭으로. ⑥ **의도 부합**(`scalability` 7장 4단계): 새 상한 없음(기존 상한
표의 이미지·엑셀 상한 그대로) / 비용 축 = 기존 내보내기 1회와 동일(진입 재배선뿐 —
이미지 포함 비용은 이미 존재하는 경로의 것) / 스냅샷 무관 / **엑셀 왕복 무변경**(파일
형식·시트 규약 불변 — 옵션 기본값 프리셋만 다름). ⑦ **텍스트** — 신설 문구 전부
strings.xml + 목적문 2건 + 검사 통과(구현 세션).

## 6. 적대 자기 검토 — 예상 반론과 답

| 반론 | 답 |
|------|-----|
| 전체 백업이 수 GB·수 분이면? | D5 결정형 진행도 + 취소, D6 사전 견적 고지. 크기 자체는 현행 '이미지 체크' 경로와 동일 — 새 비용이 아니라 보이게 된 비용이다 |
| '지금 백업'과 '전체 백업'을 헷갈린다 | D2의 한 줄 고지가 관계를 명시("내부 스냅샷 vs 반출용 사본"). 같은 화면에서 위/아래로 분리 배치 |
| 이미지 0장 사용자에게 D1은 과장 아닌가 | 기존 `export_images_none` 고지가 "이미지가 없어 .xlsx만 내보냈습니다"로 정확히 말한다(R-17 — 확장자도 실물 파생) |
| '골라서'에서 이미지를 켜는 사용자가 여전히 마지막 스크롤을 놓친다 | 그 경로의 직업은 데이터 작업이라 기본 꺼짐이 옳다(D3). 백업 직업은 D1이 가져갔으므로 "몰라서 반쪽"의 경로 자체가 사라진다 |
| 자동 백업도 이미지를 기본 포함해야 완전하지 않나 | 저장 공간 실측(백업 이미지 ×N벌 상주 — 앱 3GB의 주범)이 뒤집은 결정이다. 매일×보관 N개의 곱은 D1(수동 1회)과 비용 자릿수가 다르다 — D4 유지 |
| 실행 중 앱 이탈(B-56 부류) | D2는 WorkManager라 무관(상태 카드가 결과 보관). D1은 현행 내보내기와 동일 제약 — B-56이 그대로 든다(이 재편이 새로 만들지도, 해소하지도 않음) |
| 규칙 2(채움 버튼 화면당 1) 위반? | D1은 목록 행 스타일(강조는 배치 순서로) — 채움 버튼 신설 없음 |

**의도적으로 남기는 것:** '백업 내보내기'(.enc 반출)와 '전체 백업'의 관계 고지는 D2의
한 줄에 얹지 않는다 — 그 행은 기기 이전 캡션(`backup_device_bound_caption`)이 이미
안내하고 있고, 문구를 늘리는 것이 이 재편의 반대 방향이다.
