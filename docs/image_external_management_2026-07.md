# 이미지 링크·관리의 앱 밖(외부) 경로 — 논의 문서 (2026-07)

> **위상: 논의 전용 — 구현 아님.** 사용자 요청("이미지의 링크 및 관리를 인앱 말고 바깥에서도
> 할 수 있게는 못하나? 구현 바로 하는 게 아니라 논의가 우선")에 따라 현황·격차·선택지를
> 정리한다. 결정(6장)이 내려지기 전에는 코드에 얹지 않는다.

## 1. 질문의 분해

"이미지를 바깥에서 관리한다"는 실제로 네 가지 작업으로 갈린다. 각각 성격과 난이도가 다르다:

| # | 작업 | 뜻 |
|---|---|---|
| ① | **배정 편집** | 어느 이미지가 어느 캐릭터(작품·세계관)의 것인지 바깥에서 바꾸기 |
| ② | **링크 편집** | "같은 캐릭터 묶음"(링크 그룹)을 바깥에서 만들고 풀기 |
| ③ | **태그 편집** | 이미지 태그를 바깥에서 달고 떼기 |
| ④ | **파일 관리** | 이미지 파일 자체를 바깥에서 넣고 빼고 교체하기 |

## 2. 이미 되는 것 (현황 — 대부분 엑셀 왕복이 이미 커버한다)

엑셀 왕복(G3)과 이번 캐릭터 자동 링크(G4)를 합치면 ①②③의 상당 부분이 **이미 동작한다**:

- **① 배정 편집 — 된다.** 세계관·작품·캐릭터 시트에 '이미지' 열이 있고, 가져오기가 이를
  반영한다(빈 칸으로 기존 이미지를 지우는 경우 요약 고지 — F1-A). zip(이미지 포함) 복원이면
  경로가 재매핑되고, xlsx 단독 왕복이면 같은 기기의 기존 파일에 다시 이어진다.
- **② 링크 편집 — 자동 링크 도입으로 성격이 바뀌었다.** 자동 링크(기본 켜짐)에서 "같은
  캐릭터 묶음"은 배정에서 **파생**된다: 바깥에서 ①(배정)을 고쳐 가져오면, 가져오기 직후
  재동기화가 링크를 그 배정대로 다시 세운다(다른 기기·재발급 id로 낡은 `char:<id>` 토큰도
  치유). 즉 **외부 링크 관리의 최우선 수요는 외부 배정 관리로 이미 충족된다.**
  - 수동 링크(UUID 토큰)도 '이미지' 시트(파일명/태그/링크그룹)로 왕복은 된다 — 내보낸 토큰을
    보존해 재가져오기가 멱등이고, 가져온 그룹은 합산 2장 이상일 때만 반영된다.
- **③ 태그 편집 — 된다.** '이미지' 시트의 태그 열은 편집 전제로 설계돼 있다(열이 없으면
  기존 유지, 열이 있고 빈칸이면 비움 의도 존중 — F1-A).
- **④ 파일 관리 — 반쪽.** zip 내보내기·가져오기로 반출·재유입은 되지만, "PC 폴더에서
  파일을 추가하면 앱에 나타난다" 같은 상시 연동은 없다. 유입은 이미지 탭 임포트/픽커뿐.

## 3. 격차 (아직 안 되거나 어색한 것)

- **G-A. 수동 링크의 외부 '생성' UX가 없다.** '이미지' 시트의 링크그룹 열은 읽기 전용
  서식(회색)이라 "고치지 말라"는 신호를 준다. 실제로는 가져오기가 읽지만, 이 규약이
  사용 안내 시트에 문서화되어 있지 않아 사용자는 알 길이 없다. 새 그룹을 만들려면 토큰
  문자열을 손으로 지어내야 한다는 것도 안내가 없다(아무 문자열이나 같으면 묶인다).
- **G-B. 이미지 중심의 배정 뷰가 없다.** 배정 편집(①)은 캐릭터 시트 쪽 '이미지' 열에
  흩어져 있다. "이 이미지가 누구 것인가"를 한 열에서 보는 이미지 중심 편집(이미지 시트에
  '배정' 열)은 없다. 같은 정보의 다른 축이므로 있으면 편하지만, 두 축의 **충돌 처리 규칙**
  (캐릭터 시트와 이미지 시트가 서로 다른 배정을 말할 때)이 필요해진다.
- **G-C. 파일 폴더 상시 연동이 없다** (④의 나머지 반쪽). 지정 폴더(SAF)를 앱이 읽어
  신규 파일을 라이브러리로 편입하는 흐름.
- **G-D. 자동 링크 토큰의 외부 표기.** 내보낸 링크그룹 열에 `char:<id>`가 그대로 실린다.
  왕복은 정확하지만(재동기화가 id를 치유), 사람이 읽기엔 낯설다 — 안내 한 줄이면 족한가,
  표기를 바꿔야 하는가.

## 4. 선택지 비교

### A안. 엑셀 왕복을 공식 외부 관리 경로로 승격 (문서화 + 소폭 보강)

- 내용: ⑴ 사용 안내 시트에 이미지 시트 편집 규약 기재(태그·링크그룹 편집법, `char:` 토큰
  설명 — G-A·G-D 해소) ⑵ 링크그룹 열의 읽기 전용 서식 해제(편집 가능 신호로) ⑶ (선택)
  이미지 시트에 '배정' 열 추가(G-B — 충돌 규칙 설계 필요: 제안은 "이미지 시트가 나중에
  읽히므로 이미지 시트 우선 + 요약 고지").
- 장점: 기존 자산(왕복 무결성·검증·고지 체계) 위에 얹는 최소 공사. 개발 의도의 "엑셀
  인풋·아웃풋의 자유로움" 축과 정확히 일치. PC에서 수백 장을 일괄 정리하는 실사용에 강함.
- 단점: '상시' 연동은 아님(내보내기→편집→가져오기 사이클). ⑶은 충돌 규칙만큼 복잡도 증가.

### B안. 폴더 연동 (SAF 지정 폴더 스캔)

- 내용: 사용자가 지정한 폴더를 열 때마다(또는 수동 새로고침으로) 스캔해 신규 파일을
  라이브러리(미배정)로 편입. 파일명 규약(예: `이름#태그1#태그2.jpg`)으로 태그까지 실어
  나르는 변형도 가능.
- 장점: ④의 나머지 반쪽을 채움. 갤러리 앱·PC 파일 관리자와의 직접 연동.
- 단점: 공사 큼. 안드로이드 백그라운드 파일 감시 제약으로 "상시"가 아니라 "열 때 스캔"이
  현실적. 외부에서 파일을 **지운** 경우의 유실 처리(참조 중인 파일 소실 → 고지·복구 경로)
  설계가 무겁다. 파일명 규약은 OS 파일명 제약(길이·특수문자)과 충돌 위험.

### C안. 현상 유지 + 안내만

- 내용: 기능 추가 없이, 이미 되는 것(2장)을 사용 안내 시트·도움말에 문서화만 한다.
- 장점: 공사 0. 단점: G-A~G-C 격차가 그대로 남는다.

## 5. 제안 (논의용 초안 — 결정 아님)

1. **1순위: A안 ⑴⑵** — 이미 동작하는 왕복을 "숨은 기능"에서 "공식 기능"으로. 공사가
   문서·서식 수준이라 위험이 거의 없고, 사용자 요청("바깥에서도")의 핵심을 즉시 충족한다.
2. **2순위: A안 ⑶ (이미지 시트 '배정' 열)** — 충돌 규칙을 이 문서에서 합의한 뒤 진행.
3. **보류: B안** — A안 사용 후에도 "파일을 폴더째 넣고 싶다"는 수요가 확인되면 착수.
   착수 시에도 "열 때 스캔 + 신규만 편입 + 소실은 기존 스테일 정리 규약 재사용"의 보수적
   형태부터.
