## 0. 확정 결정 요약 (2026.07.28)

| # | 결정 | 근거 요약 |
|---|---|---|
| D1 | **본공사 = 폴더 왕복** (정리 폴더 + 이름 토큰 규약, 아래 D3~D5) | 실사용 편의는 유입·정리 마찰 해소에서 나온다(사용자 지적). 양방향 동기화가 아니라 "단방향 유입 + 사본 재배열 반영"이라 유실 경로가 없다 |
| D2 | 엑셀 링크그룹 열 개방(서식 해제 + 사용 안내 문서화)은 **폴더 왕복 작업의 곁다리**로 축소 채택 | 기존 이미지 수백 장의 일괄 링크는 엑셀이 가장 빠르나, 일상 편의는 아니다. 단독 작업 가치가 없어 얹어 간다 |
| D3 | 폴더 규약: **폴더명 = 캐릭터 일치 → 배정(자동 링크가 묶음), 불일치 → 미배정 + 그 폴더끼리 링크 세트** | "폴더 단위로 묶기"(사용자 요구)가 배정 파생 + 링크 세트로 완전 충족. 오타 폴더도 세트로 묶여 들어와 한 장만 배정하면 전체가 따라간다(부드러운 실패) |
| D4 | 내보내기 이름 규약: **`[라벨]-[번호].[토큰].jpg`** — 정체성은 토큰(내부 UUID 유래), 라벨은 사람용 | 돌아온 파일의 매칭 문제(폴더 왕복의 최대 난제)를 내용 지문 없이 해결(사용자 아이디어). 토큰 매칭 = 중복 유입 원천 차단 |
| D5 | 받아온 원본은 정리 폴더 안 `_처리됨/`으로 **이동**. 스캔은 **이미지 탭 진입 감지 + 수동 새로고침** | 폴더가 깨끗하게 유지되고 중복 방지가 구조로 해결. 안드로이드 제약상 상시 감시 대신 열 때 스캔 |
| D6 | **진행도 규약(R-26)**: 항목 순회형 대량 작업은 공용 진행도(총량·현재·단계) 의무, 조회형 로딩은 제외 | 총량을 모르는 로딩의 퍼센트는 가짜 진행도(90% 정지·0→100 깜빡임)가 된다 — 사실 고지 철학 위반. 폴더 왕복은 처음부터 포함, 기존 작업 소급은 백로그(B-51) |
| D7 | 구현 순서: **PR-1 받아오기(+공용 진행도 컴포넌트+D2 곁다리) → PR-2 정리용 내보내기** | 읽는 쪽 로직이 공유되므로 하나로 설계하고 구현만 쪼갠다. PR-1만으로 신규 유입·폴더 묶음이 완성된다 |
| D8 | **보류**: 이미지 시트 '배정' 열(B-52) · 파일명 태그 규약 · 내용 지문 보조 매칭(B-53) · 양방향 동기화(영구 반려) | 하단 4·6장 참조 — 보류 사유와 재개 조건을 백로그에 남긴다 |

결정 과정에서 정정된 판단 하나를 기록한다: v0.1은 "A안(엑셀 승격) 1순위, B안(폴더) 보류"를
제안했으나, 이는 B안을 양방향 동기화로 넓게 잡아 위험을 과대평가하고 **유입 워크플로의 일상
마찰**(실사용 편의의 실체 — 사용자 지적)을 과소평가한 것이었다. 폴더 왕복(단방향 + 토큰)으로
좁히면 위험 대부분이 사라지고 편의는 그대로다.

## 1. 질문의 분해

"이미지를 바깥에서 관리한다"는 실제로 네 가지 작업으로 갈린다. 각각 성격과 난이도가 다르다:

| # | 작업 | 뜻 | 결정 후 상태 |
|---|---|---|---|
| ① | **배정 편집** | 어느 이미지가 어느 캐릭터(작품·세계관)의 것인지 바깥에서 바꾸기 | 엑셀로 가능(기존) + 폴더 왕복으로 확장(D1·D3) |
| ② | **링크 편집** | "같은 캐릭터 묶음"(링크 그룹)을 바깥에서 만들고 풀기 | 배정에서 파생(자동 링크) + 링크 세트 폴더(D3) + 엑셀 열 개방(D2) |
| ③ | **태그 편집** | 이미지 태그를 바깥에서 달고 떼기 | 엑셀로 가능(기존 그대로) |
| ④ | **파일 관리** | 이미지 파일 자체를 바깥에서 넣고 빼고 교체하기 | 폴더 왕복이 유입·재배열 커버(D1). 삭제는 인앱 전용 유지 |

## 2. 결정의 전제가 된 현황 (엑셀 왕복 + 자동 링크)

- **① 배정 편집 — 이미 된다.** 세계관·작품·캐릭터 시트에 '이미지' 열이 있고, 가져오기가 이를
  반영한다(빈 칸으로 기존 이미지를 지우는 경우 요약 고지 — F1-A). zip(이미지 포함) 복원이면
  경로가 재매핑되고, xlsx 단독 왕복이면 같은 기기의 기존 파일에 다시 이어진다.
- **② 링크 편집 — 자동 링크(G4, PR #108) 도입으로 성격이 바뀌었다.** "같은 캐릭터 묶음"은
  배정에서 **파생**된다: 바깥에서 배정을 고쳐 가져오면 가져오기 직후 재동기화가 링크를 그
  배정대로 다시 세운다(다른 기기·재발급 id로 낡은 `char:<id>` 토큰도 치유). **외부 링크
  관리의 최우선 수요는 외부 배정 관리로 충족된다** — 이것이 D3(폴더 = 배정 = 묶음)의 근거다.
  - 수동 링크(UUID 토큰)도 '이미지' 시트(파일명/태그/링크그룹)로 왕복은 된다 — 내보낸 토큰을
    보존해 재가져오기가 멱등이고, 가져온 그룹은 합산 2장 이상일 때만 반영된다.
- **③ 태그 편집 — 된다.** '이미지' 시트의 태그 열은 편집 전제로 설계돼 있다(열이 없으면
  기존 유지, 열이 있고 빈칸이면 비움 의도 존중 — F1-A).
- **④ 파일 관리 — 반쪽이었다.** zip 왕복으로 반출·재유입은 되지만 폴더 수준의 유입 경로가
  없었다 — 이 격차가 D1의 대상이다.

## 3. 격차와 그 처분

| 격차 (v0.1) | 처분 |
|---|---|
| G-A. 수동 링크의 외부 생성 UX 부재 (링크그룹 열이 읽기 전용 서식 + 규약 미문서화) | **D2 + D3로 해소** — 링크 세트 폴더가 주 경로, 엑셀 열 개방이 보조 |
| G-B. 이미지 중심의 배정 뷰 부재 (이미지 시트 '배정' 열 없음) | **보류(D8, B-52)** — 폴더 왕복의 하위 폴더 배정이 대체. 충돌 규칙 설계 비용 대비 잔여 수요를 보고 재개 |
| G-C. 파일 폴더 상시 연동 부재 | **D1로 해소** (상시 감시가 아니라 열 때 스캔 — 안드로이드 제약의 현실적 형태) |
| G-D. 자동 토큰(`char:<id>`)의 외부 표기가 낯설다 | **D4로 해소** — 폴더 내보내기의 라벨이 사람용 표기를 제공. 엑셀 쪽은 그대로 두고 사용 안내 한 줄(D2에 포함) |

## 4. 검토했던 선택지 (기록)

- **A안. 엑셀 왕복 승격**: 문서화 + 서식 해제 + (선택) '배정' 열. → **곁다리로 축소 채택(D2)**,
  '배정' 열은 보류(B-52). 단독으로는 일상 편의 개선이 없다는 사용자 지적이 결정적이었다.
- **B안. 폴더 연동**: v0.1은 양방향 동기화 상정으로 "무겁고 위험"으로 평가했다. →
  **단방향 폴더 왕복으로 재정의해 본공사 채택(D1)**. 외부 삭제 = 유실 경로는 "앱이 사본을
  소유하고, 폴더에 없음 ≠ 삭제" 원칙으로 원천 제거된다. 양방향 동기화(외부 폴더가 원본)는
  계속 반대 — 참조 파일의 외부 삭제·SAF 성능·백업 의미론 문제로 **영구 반려**.
- **C안. 현상 유지 + 안내만**: 격차가 그대로 남아 기각.

## 5. 함께 확정된 인접 규약 — 진행도 (D6)

폴더 왕복처럼 오래 걸릴 수 있는 작업의 로딩 표시에 대한 사용자 질문("모든 로딩창에
진행도를 기본으로?")에서 나온 결정:

- **작업형 로딩**(항목 순회 대량 처리 — 가져오기/내보내기·재압축·일괄 작업·폴더 스캔·복원):
  총량을 알 수 있으므로 **결정형 진행도("몇 % · N/M장 · 현재 단계") 의무**. 공용 컴포넌트로
  통일하고, 안전한 작업에는 취소를 제공한다.
- **조회형 로딩**(화면 데이터 읽기·통계 계산): 총량을 모르고 대부분 1초 미만 — 퍼센트를
  붙이면 0→100 깜빡임(노이즈) 아니면 90% 정지(거짓말)가 된다. **가짜 진행도 금지**,
  기존 스피너 유지 + 지연 노출(0.3~0.5초)만 다듬는다.
- 규약 R-26으로 등재(원문은 `docs/conventions.md` — 2026.07.29에 `remaining_work` 1장에서 분리됐다). 현황: 엑셀 가져오기만 텍스트
  진행도(단계+%)가 있고, 내보내기·재압축·일괄 삭제 등은 스피너뿐 — 소급 적용은 백로그
  B-51(1순위: 이미지 대량 작업, 2순위: 엑셀 내보내기·가져오기 컴포넌트 이전).

## 6. 남은 것 (전부 백로그 등재 — 결정 대기 없음)

1차 범위의 미결정 사항은 **없다**. 보류분은 재개 조건과 함께 백로그에 있다:
- **B-51** 진행도 소급 적용 (R-26의 기존 작업 확산)
- **B-52** 이미지 시트 '배정' 열 (재개 조건: 폴더 왕복 사용 후에도 "엑셀에서 이미지 중심으로
  배정을 일괄 편집하고 싶다"는 수요가 확인될 때. 착수 시 캐릭터 시트와의 충돌 규칙이 선결)
- **B-53** 폴더 왕복 2차 후보: 내용 지문 보조 매칭(토큰 지운 개명 구제) · 파일명 태그 규약
  (재개 조건: 1차 사용에서 매칭 실패·태그 수작업이 실제 마찰로 확인될 때)
